Git 完整學習筆記

從基礎操作到公司實際開發流程，掌握每天都會用到的 Git 指令與最佳實踐

新版 vs 舊版指令說明

Git 2.23（2019年）新增了 git switch 和 git restore，讓原本由 git checkout 一手包辦的功能拆成兩個語意更清楚的指令。兩組指令功能完全相同，你用哪個都可以。

用途🆕 新版（Git 2.23+）📦 舊版
切換分支git switch 分支名git checkout 分支名
建立並切換分支git switch -c 新分支git checkout -b 新分支
還原工作目錄檔案git restore 檔案git checkout -- 檔案
取消暫存git restore --staged 檔案git reset HEAD 檔案
查看暫存區差異git diff --stagedgit diff --cached（完全相同）
📦 關於本筆記的標示方式 本筆記在每個有新舊差異的指令旁，都會以 ▶ 舊版 標示對應的舊版寫法，讓你新舊都看得到，不會混淆。

Git 的三個區域

理解這三個區域是學 Git 最重要的基礎，所有指令都圍繞著這三個區域在移動資料：

工作目錄 (Working Directory)    │ git add    ▼ 暫存區 (Staging Area / Index)    │ git commit    ▼ 本地儲存庫 (Local Repository)    │ git push    ▼ 遠端儲存庫 (Remote Repository)
📁

工作目錄

你實際在電腦上編輯的檔案，未追蹤的變更

📋

暫存區

準備要 commit 的變更，git add 後進入

🗄️

本地 Repo

commit 後的永久記錄，存在 .git 資料夾

☁️

遠端 Repo

GitHub / GitLab，push 後團隊共用

檔案的四種狀態

狀態說明如何進入
Untracked新檔案，Git 還不認識建立新檔案
Modified已追蹤但有變更，未暫存編輯已 commit 的檔案
Staged已暫存，準備 commitgit add
Committed已提交，安全儲存git commit
入門

初始設定

第一次使用 Git 或加入新公司時的必要設定

全域設定（第一次用 Git）

# 設定名字與 Email（commit 記錄會顯示）
git config --global user.name  "Cooper Chen"
git config --global user.email "cooper@example.com"

# 設定預設編輯器（選一個）
git config --global core.editor "code --wait"  # VS Code
git config --global core.editor "vim"

# 設定預設分支名稱為 main（新版 Git 推薦）
git config --global init.defaultBranch main

# 查看所有設定
git config --list
BASH

建立或取得 Repo

# 建立全新 repo（在現有資料夾）
git init

# 複製現有 repo（加入公司時最常用）
git clone https://github.com/company/project.git

# clone 並指定本地資料夾名稱
git clone https://github.com/company/project.git my-project

# clone 只取特定分支（大型 repo 加速）
git clone --branch develop --single-branch https://github.com/company/project.git
BASH

.gitignore — 排除不需要追蹤的檔案

# .gitignore 範例（前端專案）
node_modules/
dist/
.env
.env.local
.env.*.local
*.log
.DS_Store         # macOS 系統檔
Thumbs.db         # Windows 系統檔
.vscode/          # 看團隊習慣，有時共用
.nuxt/
.output/
GITIGNORE
💡 .gitignore 已追蹤的檔案 如果檔案已經被 commit 過，之後加入 .gitignore 不會自動取消追蹤。需要手動執行：
git rm --cached 檔案名稱，再 commit 一次。

基本操作

每天都會用到的核心指令

查看狀態

# 查看當前狀態（最常用）
git status

# 簡短版本
git status -s
# 輸出：
 M README.md     # 已修改（已暫存）
 M src/app.vue   # 已修改（未暫存）
?? newfile.js    # 未追蹤
BASH

加入暫存區

🆕 新版（Git 2.23+）
📦 舊版
# 加入單一檔案
git add src/components/Button.vue

# 加入整個資料夾
git add src/

# 加入所有變更（最常用）
git add .

# 互動式選擇要加入哪些部分（同一個檔案分多次 commit）
git add -p

# 取消暫存（把檔案從 staging area 移回工作目錄）
git restore --staged src/app.vue
BASH
# 加入單一檔案
git add src/components/Button.vue

# 加入整個資料夾
git add src/

# 加入所有變更（最常用）
git add .

# 互動式選擇要加入哪些部分（同一個檔案分多次 commit）
git add -p

# 取消暫存（把檔案從 staging area 移回工作目錄）
git reset HEAD src/app.vue
BASH

提交 Commit

# 標準提交
git commit -m "feat: add login form validation"

# 跳過 git add，直接提交所有已追蹤檔案的變更
git commit -am "fix: correct typo in header"

# 修改最後一次 commit（還沒 push 才能用）
git commit --amend -m "feat: add login form"

# 修改最後一次 commit，只改訊息（不改檔案）
git commit --amend --no-edit  # 訊息不變，只加入新的暫存變更
BASH
⚠️ --amend 只能用在還沒 push 的 commit 如果已經 push 到遠端，amend 會改變 commit hash，強制 push 會影響所有協作者。已 push 的 commit 用 git revert 代替。

分支操作

分支是 Git 的核心優勢，讓多人開發互不干擾

查看 & 建立分支

# 查看所有本地分支（* 是當前分支）
git branch

# 查看所有分支（含遠端）
git branch -a

# 查看遠端分支
git branch -r

# 建立新分支
git branch feature/login

# 建立並立刻切換（最常用）
git switch -c feature/login

# 從指定分支建立
git switch -c feature/login develop
BASH

切換 & 刪除分支

🆕 新版（Git 2.23+）
📦 舊版
# 切換分支
git switch develop

# 切回上一個分支（- 代表上一個）
git switch -

# 刪除已合併的分支（安全）
git branch -d feature/login

# 強制刪除（未合併也刪）
git branch -D feature/login

# 刪除遠端分支
git push origin --delete feature/login

# 重新命名分支
git branch -m old-name new-name
BASH
# 切換分支
git checkout develop

# 切回上一個分支
git checkout -

# 刪除已合併的分支（安全）
git branch -d feature/login

# 強制刪除（未合併也刪）
git branch -D feature/login

# 刪除遠端分支（相同）
git push origin --delete feature/login

# 重新命名分支（相同）
git branch -m old-name new-name
BASH

分支命名慣例（公司常用）

類型格式範例
功能開發feature/描述feature/user-login
Bug 修復fix/描述 或 bugfix/描述fix/navbar-overflow
緊急修復hotfix/描述hotfix/payment-crash
重構refactor/描述refactor/auth-module
文件docs/描述docs/api-readme
發版release/版本號release/v1.2.0

遠端操作

與 GitHub / GitLab 的互動，協作開發的基礎

遠端管理

# 查看遠端設定
git remote -v
origin  https://github.com/company/project.git (fetch)
origin  https://github.com/company/project.git (push)

# 新增遠端（通常 clone 後自動設定 origin）
git remote add origin https://github.com/company/project.git

# 修改遠端 URL
git remote set-url origin https://github.com/company/new-project.git
BASH

fetch / pull / push

# fetch：下載遠端更新，但不合併（安全）
git fetch origin
git fetch --all  # 所有遠端

# pull：下載 + 合併（= fetch + merge）
git pull                    # 預設 origin 當前分支
git pull origin develop    # 指定遠端和分支

# pull 用 rebase 代替 merge（保持線性歷史）
git pull --rebase

# push：推送到遠端
git push origin feature/login

# 第一次推送新分支，設定追蹤關係
git push -u origin feature/login
# 之後在這個分支只需要
git push

# 強制推送（⚠️ 危險！只在個人分支使用）
git push --force-with-lease  # 比 --force 更安全的版本
BASH
⚠️ 不要對 main / develop 使用 force push force push 會改寫遠端歷史，讓所有協作者的本地 repo 與遠端不同步。只在自己的 feature branch 且確定沒有其他人使用時才用。

追蹤遠端分支

🆕 新版（Git 2.23+）
📦 舊版
# 切換到遠端已有的分支（自動建立追蹤）
git switch develop

# 手動設定追蹤
git branch --set-upstream-to=origin/develop develop
BASH
# 切換到遠端已有的分支（-t 同時設定追蹤）
git checkout -t origin/develop
# 或先 fetch 後再 checkout
git fetch origin
git checkout develop

# 手動設定追蹤（相同）
git branch --set-upstream-to=origin/develop develop
BASH
中階

Merge & Rebase

合併分支的兩種方式，以及衝突解決

Merge — 合併分支

🆕 新版（Git 2.23+）
📦 舊版
# 把 feature/login 合併進 develop
git switch develop
git merge feature/login

# --no-ff：強制建立 merge commit（保留分支歷史）
git merge --no-ff feature/login

# --squash：把分支所有 commit 壓成一個
git merge --squash feature/login
git commit -m "feat: add login feature"
BASH
# 把 feature/login 合併進 develop
git checkout develop
git merge feature/login

# --no-ff（相同）
git merge --no-ff feature/login

# --squash（相同）
git merge --squash feature/login
git commit -m "feat: add login feature"
BASH

Rebase — 變基

🆕 新版（Git 2.23+）
📦 舊版
# 情境：main 有新 commit，feature 要跟上最新進度

# Merge 方式（會多一個 merge commit）
git switch feature/login
git merge main

# Rebase 方式（把 feature 的 commit 接在 main 最新 commit 後）
git switch feature/login
git rebase main
BASH
# 情境：main 有新 commit，feature 要跟上最新進度

# Merge 方式
git checkout feature/login
git merge main

# Rebase 方式
git checkout feature/login
git rebase main
BASH
Merge 結果： main: A ─ B ─ C ─ ─ ─ ─ M \ / feature: A ─ B ─ D ─ E ─ ┘ Rebase 結果（線性，更乾淨）： main: A ─ B ─ C feature: └─ D' ─ E'

衝突解決（Conflict）

# 合併時出現衝突，Git 會在檔案中標記
<<<<<<< HEAD（你的版本）
const title = 'My App'
=======
const title = 'Company App'
>>>>>>> feature/login（對方的版本）

# 步驟：
# 1. 手動編輯衝突檔案（刪掉 <<<< ==== >>>> 標記，保留正確內容）
# 2. 加入暫存
git add src/app.vue

# 3. 完成合併
git commit  # merge 用這個
git rebase --continue  # rebase 用這個

# 放棄合併/rebase
git merge  --abort
git rebase --abort
BASH
MergeRebase
歷史記錄保留完整分支結構線性，更乾淨
Commit 數多一個 merge commit不多餘 commit
安全性較安全，不改 commit⚠️ 改寫歷史，共用分支禁用
適用場景合併進 main/developfeature branch 同步最新 main
中階

Stash 暫存

臨時保存工作進度，切換任務後再恢復

情境：你正在寫 feature，突然要切去修一個緊急 bug，但目前的程式碼還沒準備好 commit。

# 暫存當前工作目錄的所有變更
git stash

# 暫存並加上描述（推薦）
git stash push -m "WIP: login form half done"

# 包含 untracked 的新檔案
git stash push -u -m "WIP: with new files"

# 查看所有 stash
git stash list
stash@{0}: On feature/login: WIP: login form half done
stash@{1}: On develop: WIP: navbar experiment

# 恢復最新的 stash（保留 stash 記錄）
git stash apply

# 恢復並刪除 stash 記錄（最常用）
git stash pop

# 恢復指定的 stash
git stash pop stash@{1}

# 刪除指定 stash
git stash drop stash@{0}

# 刪除所有 stash
git stash clear

# 查看 stash 內容
git stash show -p stash@{0}
BASH
💡 實際工作流 1. 正在寫 feature/login，臨時要修 bug
2. git stash push -m "WIP: login"
3. git switch hotfix/urgent-bug
4. 修好 bug、commit、push
5. git switch feature/login
6. git stash pop — 恢復之前的工作
中階

還原操作

reset、revert、restore — 後悔藥三兄弟

restore — 還原工作目錄

🆕 新版（Git 2.23+）
📦 舊版
# 放棄工作目錄的修改，還原到最後一次 commit（⚠️ 不可恢復）
git restore src/app.vue
git restore .  # 還原所有

# 把暫存區的檔案退回工作目錄（取消 git add）
git restore --staged src/app.vue
BASH
# 放棄工作目錄的修改（⚠️ 不可恢復）
# 注意：-- 後面加檔案路徑
git checkout -- src/app.vue
git checkout -- .  # 還原所有

# 把暫存區的檔案退回工作目錄（取消 git add）
git reset HEAD src/app.vue
git reset HEAD  # 取消所有暫存
BASH

reset — 移動 HEAD 位置

# --soft：HEAD 往回移，commit 取消，但變更保留在暫存區
git reset --soft HEAD~1   # 取消最後一個 commit
git reset --soft HEAD~3   # 取消最後三個 commit

# --mixed（預設）：HEAD 往回移，變更退回工作目錄
git reset HEAD~1
git reset abc1234          # 回到指定 commit

# --hard：HEAD 往回移，變更完全丟棄（⚠️ 危險）
git reset --hard HEAD~1
git reset --hard origin/main  # 強制同步遠端（丟棄本地變更）
BASH
模式Commit暫存區工作目錄適用場景
--soft移除保留保留重新整理最後幾個 commit
--mixed移除清空保留取消 commit，重新修改
--hard移除清空清空完全放棄，回到乾淨狀態

revert — 安全地撤銷已 push 的 commit

# 建立一個「反向 commit」來撤銷，不改寫歷史
# 已 push 到遠端的 commit 必須用 revert，不能用 reset

git revert abc1234         # 撤銷指定 commit
git revert HEAD            # 撤銷最後一個 commit
git revert HEAD~3..HEAD    # 撤銷最後三個 commit

# 不自動 commit（讓你可以先看結果）
git revert --no-commit abc1234
BASH
💡 reset vs revert 選哪個？ 還沒 push：用 reset（可以任意改寫歷史）
已經 push：一定要用 revert（建立反向 commit，不影響他人）

git diff

🆕 新版
📦 舊版（--cached）
# 查看工作目錄與暫存區的差異
git diff

# 查看暫存區與最後 commit 的差異
git diff --staged

# 比較兩個分支的差異
git diff main..feature/login

# 只顯示有差異的檔案名稱
git diff --name-only main..feature/login
BASH
# 查看工作目錄與暫存區的差異（相同）
git diff

# 查看暫存區與最後 commit 的差異
# --cached 是 --staged 的舊名稱，功能完全相同
git diff --cached

# 比較兩個分支的差異（相同）
git diff main..feature/login

# 只顯示有差異的檔案名稱（相同）
git diff --name-only main..feature/login
BASH

git blame — 追查每行的修改者

# 查看每一行是誰、什麼時候修改的
git blame src/components/Login.vue

團隊工作流

實際公司開發最常用的 Feature Branch Flow

Feature Branch Flow（最常見）

main ●─────────────────────────────● v1.0 \ / develop ●───●───●───────●───●───● \ / feature ●───●

完整的日常開發流程

1

同步最新的 develop

🆕 新版
📦 舊版
git switch develop
git pull origin develop
git checkout develop
git pull origin develop
2

從 develop 建立 feature 分支

🆕 新版
📦 舊版
git switch -c feature/user-login
git checkout -b feature/user-login
3

開發功能、定期 commit

git add .
git commit -m "feat: add login form UI"
# ... 繼續開發 ...
git commit -m "feat: add login API integration"
4

Push 到遠端，開 PR

git push -u origin feature/user-login
# 到 GitHub / GitLab 開 Pull Request
5

Code Review 期間有修改，繼續 push

git commit -m "fix: address review comments"
git push
6

PR 核准後，合併進 develop（通常由 GitHub 操作）

# GitHub 上點 Merge Pull Request
# 或本地操作：
git switch develop
git merge --no-ff feature/user-login
git push origin develop
# ── 舊版同上，git switch → git checkout ──
7

刪除已合併的 feature 分支

git branch -d feature/user-login
git push origin --delete feature/user-login

Hotfix 緊急修復流程

🆕 新版（Git 2.23+）
📦 舊版
# 1. 從 main 建立 hotfix 分支
git switch main
git switch -c hotfix/payment-crash

# 2. 修復、commit
git commit -m "fix: resolve payment calculation error"

# 3. 合併回 main（上線）
git switch main

# 4. 同步回 develop
git switch develop
git merge --no-ff hotfix/payment-crash
git push origin develop

git checkout main
git checkout -b hotfix/payment-crash

# 2. 修復、commit（相同）
git commit -m "fix: resolve payment calculation error"

# 3. 合併回 main（上線）
git checkout main
git merge --no-ff hotfix/payment-crash
git tag -a v1.0.1 -m "fix: payment crash"
git push origin main --tags

# 4. 同步回 develop
git checkout develop
git merge --no-ff hotfix/payment-crash
git push origin develop
BASH

PR & Code Review

Pull Request 是公司開發最重要的協作環節

開 PR 前的準備

# 1. 確保分支是最新的，先 rebase 到最新 develop
# （新舊版 rebase 指令本身相同，差異只在切換分支那步）
git fetch origin
git rebase origin/develop

# 如果有衝突，解決後繼續
git rebase --continue

# 2. 整理 commit（選用，讓歷史更乾淨）
# 把最後 3 個 commit 互動式整理
git rebase -i HEAD~3
# 出現編輯器，可以：
# pick  = 保留

Commit Message 規範

Conventional Commits — 讓 commit 歷史一目了然

格式

type(scope): description

# type   = 變更類型（必填）
# scope  = 影響範圍（選填）
# description = 簡短說明（必填）
FORMAT

Type 類型

Type說明範例
feat新功能feat: add user login
fixBug 修復fix: correct email validation
docs文件變更docs: update README
style格式調整（不影響功能）style: format with prettier
refactor重構refactor: extract auth logic
test測試test: add login unit tests
chore維護工作chore: update dependencies
perf效能改善perf: optimize list rendering
ciCI/CD 設定ci: add GitHub Actions
revert還原revert: feat: add user login

實際範例

# 好的 commit message ✅
feat(auth): add JWT refresh token mechanism
fix(navbar): resolve overflow issue on mobile
docs(api): add authentication endpoints documentation
refactor(store): migrate from Vuex to Pinia
chore(deps): upgrade Vue from 3.3 to 3.4
feat!: change API response format (BREAKING CHANGE)

# 不好的 commit message ❌
fix bug
update
WIP
asdfgh

💡 寫好 commit message 的原則 用祈使句、現在式：「add feature」不是「added feature」
說明「做了什麼」，不只是「改了什麼」
第一行在 72 字以內
必要時加上 body 解釋「為什麼」這樣做

進階指令

cherry-pick、tag、reflog、submodule

cherry-pick — 撿指定的 commit

# 把其他分支的某個 commit 搬過來
# 情境：develop 有個 bug fix，要快速移植到 main

git switch main              # 舊版：git checkout main
git cherry-pick a3f1c2d         # 搬一個
git cherry-pick a3f1c2d b7e9a1c  # 搬多個
git cherry-pick a3f1c2d..b7e9a1c # 搬範圍

# 搬過來但不自動 commit（先看結果）
git cherry-pick --no-commit a3f1c2d
BASH

tag — 版本標籤

# 建立輕量標籤
git tag v1.0.0

# 建立附註標籤（推薦，含說明）
git tag -a v1.0.0 -m "Release version 1.0.0"

# 對某個舊 commit 打標籤
git tag -a v0.9.0 abc1234 -m "Beta release"

# 查看所有標籤
git tag

# 推送標籤（push 預設不包含 tag）
git push origin v1.0.0       # 推送單一標籤
git push origin --tags        # 推送所有標籤

# 刪除標籤
git tag -d v1.0.0                        # 刪除本地
git push origin --delete v1.0.0          # 刪除遠端
BASH

reflog — Git 的黑盒子

# 查看本地所有 HEAD 的移動記錄（包含 reset --hard 等危險操作）
git reflog
a3f1c2d HEAD@{0}: commit: feat: add login
b7e9a1c HEAD@{1}: reset --hard: moving to HEAD~1
c2d4e5f HEAD@{2}: commit: fix: email validation
d1e2f3a HEAD@{3}: checkout: moving from main to feature/login

# 救回被 reset --hard 刪掉的 commit！
git reset --hard c2d4e5f  # 回到那個 commit
# 或建立新分支從那個點繼續
git switch -c recovered-branch c2d4e5f
                         # 舊版：git checkout -b recovered-branch c2d4e5f
BASH

互動式 Rebase — 整理 commit 歷史

# 整理最後 4 個 commit（PR 前整理常用）
git rebase -i HEAD~4

# 出現的編輯介面：
pick a3f1c2d feat: add login form
pick b7e9a1c WIP: still working
pick c2d4e5f more changes
pick d1e2f3a fix: final adjustments

# 改成：
pick a3f1c2d feat: add login form
squash b7e9a1c WIP: still working
squash c2d4e5f more changes
squash d1e2f3a fix: final adjustments
# 儲存後，4 個 commit 合成 1 個，可以編輯最終訊息
BASH

🚨 緊急救援

常見的「搞砸了」情境與解決方法

情境一：commit 了不該 commit 的檔案

# 還沒 push — 修改最後一個 commit
git rm --cached .env          # 從追蹤移除（不刪實體檔案）
git commit --amend --no-edit  # 修改 commit

# 已 push — 用 revert
git revert HEAD
git push
# 別忘了把敏感資訊失效（API key 等）
BASH

情境二：在錯誤的分支 commit 了

# 不小心在 main 上 commit，應該在 feature 分支

# 1. 先記下 commit hash
git log --oneline -1
a3f1c2d feat: add login form  ← 記下這個

# 2. 在 feature 分支 cherry-pick 過來
git switch feature/login       # 舊版：git checkout feature/login
git cherry-pick a3f1c2d

# 3. 回到 main，撤銷那個 commit
git switch main              # 舊版：git checkout main
git reset --hard HEAD~1
BASH

情境三：reset --hard 之後後悔了

# 用 reflog 找回消失的 commit
git reflog
b7e9a1c HEAD@{1}: commit: feat: important work  ← 就是這個！

git reset --hard b7e9a1c  # 回去！
BASH

情境四：merge 之後發現不對，要取消

# 剛 merge 完，還沒 push
git reset --hard ORIG_HEAD   # ORIG_HEAD 是 merge 前的位置

# 已經 push 了
git revert -m 1 HEAD         # -m 1 = 保留主線
git push
BASH

情境五：把 develop 的更新 rebase 到 feature，搞亂了

# rebase 到一半不想繼續
git rebase --abort   # 回到 rebase 前的狀態

# rebase 完發現結果很奇怪，想要整個 rebase 重來
git reflog
# 找到 rebase 前的 commit hash
git reset --hard BEFORE_REBASE_HASH
BASH

情境六：push 到錯誤的遠端分支

# 不小心 push 到 main，要撤回
# （前提：你有 main 的 push 權限，公司通常有保護）
git push origin --delete wrong-branch
# 通知團隊，請大家不要 pull
BASH
🛟 Git 的安全網 只要你 commit 過，幾乎都可以用 git reflog 找回來。reflog 預設保留 90 天。真正找不回來的只有：從未 commit 過的工作目錄變更，以及 git clean -fd 刪除的 untracked 檔案。

🆕 新版
📦 舊版

git reset --hard HEAD~1           # 相同
