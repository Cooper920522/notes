For ERP 開發 · 基礎篇

Chapter 01心智模型：C# vs JS

先建立正確的心智模型，再學語法。C# 跟 JS 表面像，骨子裡是兩種哲學。

1.1 C# 是什麼？

C# 是微軟在 2000 年推出的程式語言，運行在 .NET 平台上。它是編譯型、強型別、靜態型別、物件導向的語言。可以這樣理解：

  • 編譯型：你寫的 C# 程式碼要先被「編譯器」翻譯成中介語言（IL），再由 CLR 執行。JS 是直譯型（V8 邊讀邊執行）。
  • 強型別：型別檢查嚴格，不能隨便把字串當數字加（JS 你寫 "5" + 3 會變成 "53"，C# 直接編譯錯誤）。
  • 靜態型別：型別在編譯時就決定，宣告之後不能變（JS 是動態的，一個變數可以從 number 變成 string）。
  • 物件導向為本：所有程式碼都必須寫在類別裡（沒有 JS 那種「全域函式滿天飛」的寫法）。

1.2 .NET 平台：CLR 是什麼

JS 跑在瀏覽器引擎（如 V8）上；C# 跑在 CLR（Common Language Runtime）上。CLR 負責：

  • 把 IL（中介語言）執行起來（JIT 編譯成機器碼）
  • 管理記憶體（垃圾回收 GC，跟 JS 引擎類似的概念）
  • 提供型別系統、例外處理、執行緒、安全性

你以後會看到兩個版本名詞：

名稱說明
.NET Framework舊版（4.x 系列），只能在 Windows 上跑。很多 ERP、企業內部系統還在用。語法 C# 7.x 為主。
.NET（.NET Core 之後）新版（.NET 5/6/7/8…），跨平台（Windows/Linux/Mac），效能更好。新專案多用這個。

語法上 90% 以上共通，差別在於可用的函式庫和某些新特性。你進公司後問清楚用哪個版本就好。

1.3 跟 JS 的核心差異一覽

面向JavaScriptC#
型別系統動態、弱型別靜態、強型別
執行方式直譯（JIT 加速）編譯成 IL，再由 CLR JIT 執行
變數宣告let x = 5int x = 5;（要寫型別、要分號）
程式碼組織函式可以是頂層所有程式碼都在類別裡
記憶體都在 heap，GC 管理值型別在 stack、參考型別在 heap，GC 管 heap
null有 null 和 undefined只有 null，且預設值型別不能為 null
this 綁定動態，依呼叫方式變固定，指當前實例
繼承原型鏈（prototype）類別繼承（單一繼承）+ 介面
Why · 為什麼這些差異重要

JS 為了讓你寫得快，犧牲了型別安全；C# 為了讓大型系統可靠，要求你寫得明確。ERP 系統動輒幾十萬行程式碼、跑多年、處理錢的事——它選 C# 不是偶然，是因為「編譯期就抓到錯誤」比「上線後出包」便宜得多。

Chapter 02第一個 C# 程式

看一個最小的 C# 程式長什麼樣，理解每個元素為什麼存在。

2.1 經典寫法（傳統 C# / .NET Framework）

C#

using System;

namespace HelloWorld
{
    class Program
    {
        static void Main(string[] args)
        {
            Console.WriteLine("Hello, World!");
        }
    }
}

逐行拆解：

  • using System; — 引入命名空間，類似 JS 的 import。Console 在 System 命名空間裡。
  • namespace HelloWorld — 你自己的命名空間，避免名稱衝突。
  • class Program — 一個類別。C# 所有程式碼都必須在類別裡。
  • static void Main(...) — 程式進入點。static 表示不用建立物件就能呼叫；void 表示無回傳值。
  • Console.WriteLine — 印一行到主控台，類似 JS 的 console.log。

2.2 新寫法（.NET 6+ 的 Top-level statements）

C#

Console.WriteLine("Hello, World!");

新版本可以省略 namespace、class、Main，直接寫敘述。但 ERP 老系統大概率用的是傳統寫法，你看到完整版要習慣。

Why · 為什麼 C# 強制用類別包起來

這是「物件導向為本」的設計哲學。C# 認為：一段獨立存在的函式（如 JS 的全域函式）會讓大型程式變混亂；強制每段邏輯都歸屬於某個類別，能逼你思考「這段程式碼屬於哪個概念」。對 ERP 這種大型系統，這個強制非常有價值。

Chapter 03型別系統

這是 C# 跟 JS 最大的分水嶺。學好型別系統，C# 就學會一半。

3.1 內建基本型別

C# 型別說明JS 對應範例
int32 位元整數numberint age = 28;
long64 位元整數number / BigIntlong big = 100000000000L;
double64 位元浮點數numberdouble pi = 3.14;
decimal高精度小數（給錢用）(無)decimal price = 99.99m;
bool布林值booleanbool isOk = true;
char單一字元（用單引號）(無)char c = 'A';
string字串（用雙引號）stringstring name = "BoKai";
注意 · ERP 開發必記

處理金額一律用 decimal，不要用 double。double 是二進位浮點數，0.1 + 0.2 = 0.30000000000000004 這種事在 JS 你看過了，在處理發票、訂單金額時是災難。decimal 是十進位高精度，0.1m + 0.2m 就是 0.3m。

3.2 強型別 vs 弱型別的具體差異

JS（可以）

let x = 5;
x = "hello";   // OK
x = true;      // OK
console.log("5" + 3);  // "53"

C#（不行）

int x = 5;
x = "hello";  // 編譯錯誤！
// "5" + 3 也會錯（除非明確轉型）

3.3 型別推斷：var

C# 可以用 var 讓編譯器自己推斷型別，看起來像 JS，但骨子裡完全不同：

C#

var name = "BoKai";   // 編譯器推斷為 string
var age = 28;         // 推斷為 int
name = 123;           // 錯！name 已經被定型成 string

關鍵：var 不是「動態型別」，而是「讓編譯器幫我寫型別」。型別一旦在宣告時被推斷出來，就固定了。

3.4 型別轉換

隱式轉換（小型別自動轉大型別）

C#

int i = 100;
double d = i;  // OK，int 可以自動變 double

顯式轉換（要明確寫出來）

C#

double d = 3.14;
int i = (int)d;  // 強制轉型，小數點被截掉，i = 3

字串 ↔ 數字

C#

// 字串轉數字
string s = "123";
int n = int.Parse(s);              // 失敗會丟例外
bool ok = int.TryParse(s, out int n2);  // 失敗回 false，安全

// 數字轉字串
int x = 42;
string s2 = x.ToString();
string s3 = $"年齡：{x}";  // 內插字串，類似 JS template literal

3.5 Nullable 可為空型別

這是 C# 跟 JS 一個很大的差異：值型別預設不能為 null。

C#

int x = null;   // 錯！int 不能是 null
int? y = null;  // OK，加上 ? 表示「可為 null 的 int」

if (y.HasValue) { ... }  // 檢查有沒有值
int z = y ?? 0;          // 如果 y 是 null 就用 0（類似 JS 的 ?? ）
Why · 為什麼分這麼細

JS 的 null/undefined 滿天飛是無數 bug 的來源。C# 在型別系統就強制你想清楚：「這個變數有可能是空的嗎？」如果是，你就要明確標 ?，並且處理「空的情況」。這逼你寫出更安全的程式碼。新版 C# 連 string（參考型別）也支援這套「可為 null 註記」。

日常會一直用到的基本操作。

4.1 命名慣例

4.2 字串處理

C#

// 內插字串（用 $ 開頭，類似 JS 的 `${}`）
string name = "BoKai";
int age = 28;
string msg = $"Hi {name}, 你 {age} 歲";

// 多行字串（用 @ 表示逐字字串）
string sql = @"SELECT id, name
               FROM users
               WHERE age > 18";

// 兩者合用
string path = $@"C:\Users\{name}\Documents";

// 常用方法
"hello".ToUpper();              // "HELLO"
"  hi  ".Trim();                // "hi"
"a,b,c".Split(',');             // ["a", "b", "c"]
string.Join("-", new[] {"a","b","c"});  // "a-b-c"
"hello".Contains("ell");        // true
"hello".Replace("l", "L");      // "heLLo"
"hello".Substring(1, 3);        // "ell"
string.IsNullOrEmpty(s);        // 檢查 null 或空字串
string.IsNullOrWhiteSpace(s);   // 檢查 null、空字串、或全是空白

4.3 字串是不可變的

跟 JS 一樣，C# 的 string 不可變。所有「修改」操作都是回傳新字串：

C#

string s = "hello";
s.ToUpper();         // 不會改變 s，s 仍是 "hello"
s = s.ToUpper();     // 這才會讓 s 變成 "HELLO"
效能注意

大量字串拼接要用 StringBuilder，不要用 +。每次 + 都會產生新字串，效能很差。

C#

var sb = new StringBuilder();
for (int i = 0; i < 1000; i++)
{
    sb.Append(i);
    sb.Append(",");
}
string result = sb.ToString();

4.4 運算子

大部分跟 JS 一樣（+ - * / % == != < > && ||），幾個值得注意的：

  • == 在 C# 對值型別比較值、對參考型別比較參考（沒有 JS 的 === 因為 C# 本來就是嚴格比較）
  • ?? null 合併運算子（同 JS）：x ?? "預設"
  • ?. null 條件存取（同 JS）：user?.Address?.City
  • is 型別檢查：if (obj is string s) { ... }

Chapter 05流程控制

if、迴圈、switch——跟 JS 大同小異，但有幾個 C# 獨有的好東西。

5.1 if / else

語法跟 JS 完全一樣：

C#

if (age >= 18)
{
    Console.WriteLine("成年");
}
else if (age >= 13)
{
    Console.WriteLine("青少年");
}
else
{
    Console.WriteLine("兒童");
}

// 條件運算子（同 JS 三元）
string result = age >= 18 ? "成年" : "未成年";

5.2 switch（傳統與新版）

C#

// 傳統 switch
switch (day)
{
    case 1:
    case 2:
        Console.WriteLine("週一二");
        break;
    case 3:
        Console.WriteLine("週三");
        break;
    default:
        Console.WriteLine("其他");
        break;
}

// 新版 switch expression（C# 8+，超好用）
string desc = day switch
{
    1 or 2 => "週一二",
    3 => "週三",
    >= 4 and <= 5 => "週四五",
    _ => "其他"
};

5.3 迴圈

C#

// for（同 JS）
for (int i = 0; i < 10; i++) { ... }

// while
while (count < 100) { count++; }

// do-while
do { ... } while (condition);

// foreach（類似 JS 的 for...of）
foreach (var item in list)
{
    Console.WriteLine(item);
}

// break、continue 用法同 JS
Why · foreach 跟 for 怎麼選

foreach 是「我只想拿到每個元素」；for 是「我需要索引、或要反向走、或要跳著走」。對集合操作優先用 foreach，意圖更清楚。

Chapter 06方法 Methods

C# 沒有「函式」這個獨立概念，只有「方法」（屬於類別的函式）。

6.1 基本宣告

C#

// 修飾子 回傳型別 方法名(參數型別 參數名)
public int Add(int a, int b)
{
    return a + b;
}

// 沒有回傳值用 void
public void PrintHello(string name)
{
    Console.WriteLine($"Hello, {name}");
}

6.2 跟 JS 函式的關鍵差異

面向JSC#
是否獨立存在可以是頂層函式必須在類別裡，叫「方法」
參數型別不用寫必須寫
回傳型別不用寫必須寫（或 void）
this 綁定動態固定指當前實例

6.3 預設參數、命名參數

C#

public void Greet(string name, string greeting = "Hello")
{
    Console.WriteLine($"{greeting}, {name}");
}

Greet("BoKai");                          // Hello, BoKai
Greet("BoKai", "Hi");                    // Hi, BoKai
Greet(name: "BoKai", greeting: "Hey");   // 用命名參數（順序可換）

6.4 方法多載 Overloading

同名方法、不同參數，編譯器自動依參數選對的版本。JS 沒這個（JS 是動態的，沒辦法）：

C#

public int Add(int a, int b) => a + b;
public double Add(double a, double b) => a + b;
public string Add(string a, string b) => a + b;

Add(1, 2);          // 用 int 版
Add(1.5, 2.5);      // 用 double 版
Add("a", "b");      // 用 string 版

6.5 ref、out、in 參數（JS 沒有的概念）

預設參數是「按值傳遞」（傳一份拷貝），這幾個關鍵字改變傳遞方式：

C#

// ref：傳參考，呼叫前必須已初始化
public void Double(ref int x) { x *= 2; }
int n = 5;
Double(ref n);  // n 變成 10

// out：傳參考，呼叫前不用初始化，但方法內必須賦值
public bool TryParseAge(string s, out int age)
{
    return int.TryParse(s, out age);
}
if (TryParseAge("28", out int myAge)) { ... }

// in：傳參考，但是唯讀（效能優化用，較少見）

6.6 params 可變參數

C#

public int Sum(params int[] nums)
{
    int total = 0;
    foreach (var n in nums) total += n;
    return total;
}

Sum(1, 2, 3);        // 6
Sum(1, 2, 3, 4, 5);  // 15

6.7 表達式方法（簡潔寫法）

C#

// 一行就能寫完的方法可以用 =>
public int Square(int x) => x * x;
public string FullName(string first, string last) => $"{first} {last}";

Chapter 07類別與物件導向

C# 的核心。理解類別，你就理解了 C# 的設計哲學。

7.1 類別基本結構

C#

public class Person
{
    // 欄位 (field) - 通常設為 private
    private string _name;
    private int _age;

    // 屬性 (property) - 對外的介面
    public string Name
    {
        get { return _name; }
        set { _name = value; }
    }
    public int Age { get; set; }  // 自動屬性，最常用

    // 建構子
    public Person(string name, int age)
    {
        _name = name;
        Age = age;
    }

    // 方法
    public void SayHello()
    {
        Console.WriteLine($"Hi, I'm {_name}");
    }
}

// 使用
Person p = new Person("BoKai", 28);
p.SayHello();
Console.WriteLine(p.Name);  // 透過屬性讀取
p.Age = 29;                 // 透過屬性寫入

7.2 屬性 Property（C# 的招牌特性）

屬性是「看起來像欄位、實際是方法」的東西。JS 也有 getter/setter，但 C# 用得更廣、語法更精煉：

C#

public class Product
{
    // 自動屬性（最常用）
    public string Name { get; set; }

    // 唯讀屬性（只能在建構子裡賦值）
    public int Id { get; }

    // 自訂邏輯的屬性
    private decimal _price;
    public decimal Price
    {
        get => _price;
        set
        {
            if (value < 0) throw new ArgumentException("價格不能為負");
            _price = value;
        }
    }

    // 計算屬性（沒有 setter）
    public decimal PriceWithTax => _price * 1.05m;

    // 不同存取權限
    public int Stock { get; private set; }  // 外面只能讀，類別內可寫
}

7.3 存取修飾子

修飾子意思
public任何地方都能存取
private只有同一個類別內能存取（預設值）
protected同類別 + 子類別能存取
internal同一個組件（assembly）內能存取
protected internalprotected 或 internal 任一條件

7.4 建構子

C#

public class User
{
    public string Name { get; set; }
    public int Age { get; set; }

    // 預設建構子
    public User() { }

    // 帶參數的建構子
    public User(string name, int age)
    {
        Name = name;
        Age = age;
    }

    // 建構子可以呼叫其他建構子（用 this）
    public User(string name) : this(name, 0) { }
}

7.5 static 靜態成員

靜態成員屬於「類別本身」，不屬於某個實例：

C#

public class MathHelper
{
    // 靜態方法
    public static int Square(int x) => x * x;

    // 靜態欄位
    public static readonly double Pi = 3.14159;
}

// 用法：直接用類別名呼叫，不用 new
int s = MathHelper.Square(5);
double p = MathHelper.Pi;
Why · 為什麼需要 static

有些東西天生不屬於「某個物件」，而屬於「整個概念」。例如「圓周率」不屬於某顆圓，「平方計算」也不需要一個物件來執行。用 static 表達「這個成員是工具性的、共用的」。Console.WriteLine 就是 static——你不用 new Console()。

7.6 struct（值類型的類別）

C# 有兩種「自訂型別」：class（參考型別）和 struct（值型別）。差異很重要，下一章專講：

C#

public struct Point
{
    public int X { get; set; }
    public int Y { get; set; }
}

用法上看起來一樣，但記憶體行為完全不同（見 Chapter 09）。日常 ERP 開發 90% 用 class，struct 用在「小型、不可變、值語意」的東西。

Chapter 08進階 OO：繼承、多型、介面

這套東西在 ERP 程式碼裡到處都是，必須熟悉。

8.1 繼承

C#

// 父類別
public class Animal
{
    public string Name { get; set; }
    public void Eat() => Console.WriteLine($"{Name} 在吃");
}

// 子類別（用 : 表示繼承）
public class Dog : Animal
{
    public void Bark() => Console.WriteLine("汪！");
}

Dog d = new Dog();
d.Name = "小白";
d.Eat();   // 從 Animal 繼承來的
d.Bark();  // Dog 自己的

關鍵：C# 只支援單一繼承（一個類別只能有一個父類別），但可以實作多個介面。

8.2 多型 virtual / override

子類別覆寫父類別的方法：

C#

public class Animal
{
    public virtual void Speak()  // virtual 表示「可被覆寫」
    {
        Console.WriteLine("某種聲音");
    }
}

public class Dog : Animal
{
    public override void Speak()  // override 表示「我要覆寫」
    {
        Console.WriteLine("汪！");
    }
}

Animal a = new Dog();
a.Speak();  // 印「汪！」——這就是多型：用父類別型別變數，呼叫的是子類別的方法

8.3 abstract 抽象類別

抽象類別不能被實例化，是「不完整的設計藍圖」：

C#

public abstract class Shape
{
    public abstract double Area();  // 抽象方法，子類別必須實作

    public void Print()             // 一般方法，可直接用
    {
        Console.WriteLine($"面積：{Area()}");
    }
}

public class Circle : Shape
{
    public double Radius { get; set; }
    public override double Area() => Math.PI * Radius * Radius;
}

// Shape s = new Shape();  // 錯！抽象類別不能 new
Shape s = new Circle { Radius = 5 };
s.Print();

8.4 介面 Interface

介面是「純規格」，只定義「有什麼方法」，不定義「怎麼做」：

C#

public interface IRepository
{
    void Save(string data);
    string Load(int id);
}

public class FileRepository : IRepository
{
    public void Save(string data) { /* 寫檔 */ }
    public string Load(int id) { return "..."; }
}

public class DatabaseRepository : IRepository
{
    public void Save(string data) { /* 寫 DB */ }
    public string Load(int id) { return "..."; }
}

// 用介面型別，可以塞任何實作
IRepository repo = new DatabaseRepository();
repo.Save("hello");
Why · 介面 vs 抽象類別怎麼選

抽象類別適合「has-a 繼承樹、共用部分實作」（例如各種 Shape 共用 Print 方法）。介面適合「描述能力、不繼承實作」（例如「我能被儲存」就實作 ISaveable）。一個類別只能繼承一個抽象類別，但能實作多個介面。
實務上：你在 ERP 看到 I開頭的型別（如 IUserService、IOrderRepository）全是介面。介面是現代 C# 大型專案的骨架。

8.5 sealed 與 base

C#

// sealed 表示「這個類別不能再被繼承」
public sealed class Logger { ... }

// base 用來呼叫父類別的成員
public class Dog : Animal
{
    public override void Speak()
    {
        base.Speak();      // 先呼叫父類別的版本
        Console.WriteLine("汪！");
    }
}

Chapter 09記憶體模型：值型別 vs 參考型別

這章是 C# 跟 JS 心智模型差最遠的地方。理解了它，很多 bug 你會自己預測。

9.1 兩種型別、兩個地方

值型別 Value Type參考型別 Reference Type
包含int, double, bool, char, struct, enumclass, string, array, interface, delegate
存哪Stack（堆疊）Heap（堆積），變數本身存指標在 Stack
賦值複製整個值複製指標（兩個變數指向同一個物件）
預設值0 / false（不能是 null，除非加 ?）null
GC 管理否（隨函式呼叫結束自動清）是（GC 定期回收）

9.2 賦值的差異（最重要）

值型別

int a = 5;
int b = a;   // b 拿到 a 的拷貝
b = 10;
Console.WriteLine(a);  // 5（不受影響）

參考型別

var p1 = new Person { Name = "A" };
var p2 = p1;   // p2 跟 p1 指向同一個物件
p2.Name = "B";
Console.WriteLine(p1.Name);  // "B"！同一個物件被改了
Why · 為什麼這樣設計

小型、簡單的資料（一個 int、一個座標 Point）放 stack 快，複製整份成本低。複雜物件（User、Order，可能包含一堆欄位、巢狀物件）放 heap，傳指標便宜——你不會想每次傳一個 Order 就把它整份複製一次。
JS 的設計是「全部都當參考型別處理」（除了 primitives），所以 JS 開發者不太需要想這個。但在 C# 你必須清楚知道你在處理哪一種。

9.3 傳參數時的行為

C#

void ChangeInt(int x) { x = 100; }
void ChangeUser(User u) { u.Name = "改了"; }
void ReplaceUser(User u) { u = new User { Name = "新人" }; }

int n = 5;
ChangeInt(n);
Console.WriteLine(n);  // 5（值型別，拷貝傳入）

User user = new User { Name = "原本" };
ChangeUser(user);
Console.WriteLine(user.Name);  // "改了"（同一個物件被修改）

ReplaceUser(user);
Console.WriteLine(user.Name);  // 仍是 "改了"（u 是另一個指標，重新指向新物件不影響外面）

9.4 Boxing / Unboxing（裝箱、拆箱）

值型別轉成 object（參考型別）會「裝箱」——值會被搬到 heap 包成物件。反過來叫「拆箱」。

C#

int n = 42;
object o = n;       // 裝箱：n 的值被複製到 heap
int n2 = (int)o;    // 拆箱

裝拆箱有效能成本（涉及 heap 分配），大量發生時要避免。泛型（下一章）就是為了解決這個問題誕生的。

9.5 GC 垃圾回收

跟 JS 引擎類似：當一個物件沒有任何變數指著它時，GC 會在某個時間點把它清掉。你不需要手動釋放記憶體。但要注意：

  • 避免「永遠不釋放」的參考（例如把物件存進長存的全域集合，會讓 GC 收不掉）
  • 使用 IDisposable 的物件要記得 Dispose（檔案、資料庫連線這些「非記憶體」的資源 GC 管不到，下面講）

9.6 using 與 IDisposable

檔案、DB 連線、網路連線這些「外部資源」要明確釋放：

C#

// 傳統寫法
using (var conn = new SqlConnection(connStr))
{
    conn.Open();
    // ... 用連線
}  // 離開 using 區塊自動 Dispose（釋放連線）

// 新版簡寫（C# 8+）
using var conn = new SqlConnection(connStr);
conn.Open();
// 離開當前作用域時自動 Dispose
ERP 開發必記

所有 DB 連線、檔案操作、Stream 都要用 using。忘記釋放會導致連線池耗盡、檔案鎖住等問題，這在生產環境是大事。

Chapter 10集合與泛型

日常一直用。陣列只是起點，List 和 Dictionary 才是主力。

10.1 陣列 Array

C#

// 宣告與初始化
int[] nums = new int[5];           // 5 個元素，預設都 0
int[] nums2 = new int[] { 1, 2, 3 };
int[] nums3 = { 1, 2, 3 };          // 簡寫
string[] names = new string[3];     // 預設都 null

// 存取與長度
nums[0] = 10;
int len = nums.Length;
foreach (var n in nums) Console.WriteLine(n);

陣列大小固定，新增刪除元素很麻煩。實務上更常用 List<T>。

10.2 泛型集合 List<T>

C#

List<int> numbers = new List<int>();
numbers.Add(1);
numbers.Add(2);
numbers.Add(3);
numbers.Remove(2);
int first = numbers[0];
int count = numbers.Count;

// 初始化器
var fruits = new List<string> { "apple", "banana", "cherry" };

foreach (var f in fruits) Console.WriteLine(f);

10.3 Dictionary<TKey, TValue>

類似 JS 的 Map / 物件：

C#

var ages = new Dictionary<string, int>();
ages["BoKai"] = 28;
ages["Alice"] = 30;
ages.Add("Bob", 25);

if (ages.ContainsKey("BoKai"))
    Console.WriteLine(ages["BoKai"]);

// 安全取值
if (ages.TryGetValue("Charlie", out int age)) { ... }

foreach (var kvp in ages)
    Console.WriteLine($"{kvp.Key}: {kvp.Value}");

10.4 其他常見集合

型別說明類比
HashSet<T>不重複的集合JS 的 Set
Queue<T>FIFO 佇列陣列 push + shift
Stack<T>LIFO 堆疊陣列 push + pop
IEnumerable<T>所有可被 foreach 走訪的東西的抽象JS 的 iterable

10.5 泛型 Generic（C# 的核心特性）

泛型讓你寫「型別中立」的程式碼，編譯時才決定實際型別：

C#

// 不用泛型：要為每種型別寫一個版本
public int MaxInt(int a, int b) => a > b ? a : b;
public double MaxDouble(double a, double b) => a > b ? a : b;
// ... 重複到死

// 用泛型：一個版本通吃
public T Max<T>(T a, T b) where T : IComparable<T>
{
    return a.CompareTo(b) > 0 ? a : b;
}

int m1 = Max(3, 7);          // T 自動推斷為 int
string m2 = Max("a", "b");   // T 自動推斷為 string
Why · 泛型解決什麼問題

沒有泛型的話，List 只能存 object，取出來都要強制轉型，還會有裝拆箱效能問題、執行期才發現型別錯誤。List<int> 編譯期就保證裡面都是 int，型別安全 + 效能好。所有現代 C# 集合都是泛型的。

Chapter 11LINQ：資料處理利器

如果你以前用過 JS 的 array.filter().map().reduce()，LINQ 就是 C# 的同類東西，但更強大。

11.1 LINQ 是什麼

LINQ（Language Integrated Query）讓你用「查詢」的方式操作集合、資料庫、XML。對 ERP 開發超重要——處理大量資料、寫複雜邏輯都靠它。

11.2 跟 JS array methods 對照

用途JSC# (LINQ)
過濾filter()Where()
轉換map()Select()
找第一個find()FirstOrDefault()
累加reduce()Aggregate() / Sum()
排序sort()OrderBy() / OrderByDescending()
分組(無內建)GroupBy()
是否包含some() / every()Any() / All()

11.3 實例

C#

var users = new List<User>
{
    new User { Name = "Alice", Age = 30, City = "Taipei" },
    new User { Name = "Bob", Age = 25, City = "Taichung" },
    new User { Name = "Charlie", Age = 35, City = "Taipei" }
};

// 找出台北、年齡大於 28 的人，取出名字
var names = users
    .Where(u => u.City == "Taipei" && u.Age > 28)
    .Select(u => u.Name)
    .ToList();
// ["Alice", "Charlie"]

// 排序
var sorted = users.OrderBy(u => u.Age).ToList();

// 取最年輕的
var youngest = users.OrderBy(u => u.Age).FirstOrDefault();

// 統計
int totalAge = users.Sum(u => u.Age);
double avgAge = users.Average(u => u.Age);
int count = users.Count(u => u.City == "Taipei");

// 分組
var byCity = users.GroupBy(u => u.City);
foreach (var group in byCity)
{
    Console.WriteLine($"{group.Key}: {group.Count()} 人");
}

11.4 查詢語法（另一種寫法）

LINQ 有兩種語法，上面是「方法語法」，還有「查詢語法」像 SQL：

C#

var query = from u in users
            where u.City == "Taipei" && u.Age > 28
            orderby u.Age
            select u.Name;

實務上方法語法用得多，因為更彈性、可串接。兩種選一種會就好。

Why · LINQ 為什麼這麼重要

它讓「集合操作」變得宣告式、可組合、可讀。處理 ERP 的訂單、商品、客戶資料這類需求時，LINQ 一行寫完的事，用 for 迴圈要寫十行。而且它連 SQL 查詢都能用同一套語法（透過 Entity Framework），是 .NET 生態的招牌。

Chapter 12例外處理

跟 JS 概念類似，但 C# 例外是強型別的，有更完整的階層。

12.1 try / catch / finally

C#

try
{
    int result = int.Parse(userInput);
    // ...
}
catch (FormatException ex)
{
    // 特定型別的例外
    Console.WriteLine($"格式錯誤：{ex.Message}");
}
catch (Exception ex)
{
    // 通用例外（接住所有）
    Console.WriteLine($"未預期錯誤：{ex.Message}");
}
finally
{
    // 不管有沒有錯都會執行（清理用）
    Console.WriteLine("結束");
}

12.2 拋出例外

C#

public void Withdraw(decimal amount)
{
    if (amount < 0)
        throw new ArgumentException("金額不能為負", nameof(amount));
    if (amount > _balance)
        throw new InvalidOperationException("餘額不足");
    _balance -= amount;
}

12.3 常見例外型別

型別什麼情況
ArgumentException參數值不合法
ArgumentNullException參數是 null
NullReferenceException對 null 物件呼叫成員（要避免）
InvalidOperationException物件狀態不允許這個操作
FormatException字串格式不對（如 Parse 失敗）
IndexOutOfRangeException陣列索引超出範圍
FileNotFoundException檔案不存在
SqlExceptionSQL 操作錯誤（在 ERP 會常遇到）

12.4 自訂例外

C#

public class InsufficientFundsException : Exception
{
    public decimal Balance { get; }
    public decimal Required { get; }

    public InsufficientFundsException(decimal balance, decimal required)
        : base($"餘額 {balance} 不足支付 {required}")
    {
        Balance = balance;
        Required = required;
    }
}
最佳實踐

不要用 catch (Exception) 然後吞掉錯誤——這會把問題藏起來，debug 時痛苦。要嘛只接住你能處理的特定型別，要嘛重新 throw。

Chapter 13委派、Lambda、事件

這是 C# 處理「把函式當值傳遞」的方式。對 JS 開發者來說 Lambda 最熟，委派(delegate)是 C# 比較獨特的概念。

13.1 委派 Delegate

委派是「型別化的函式指標」，相當於 JS 的 callback，但有明確的型別簽章：

C#

// 宣告委派型別
public delegate int MathOp(int a, int b);

public int Add(int a, int b) => a + b;
public int Mul(int a, int b) => a * b;

MathOp op = Add;
int r1 = op(2, 3);  // 5

op = Mul;
int r2 = op(2, 3);  // 6

13.2 內建委派：Func 和 Action

實務上很少自己宣告 delegate，直接用內建的就好：

型別用途
Action沒回傳值的方法
Action<T>吃一個參數、無回傳
Func<TResult>沒參數、有回傳
Func<T, TResult>吃 T、回傳 TResult
Func<T1, T2, TResult>吃兩個參數、回傳 TResult
Predicate<T>吃 T、回傳 bool

13.3 Lambda 表達式

跟 JS 的箭頭函式幾乎一樣：

C#

Func<int, int, int> add = (a, b) => a + b;
Func<int, int> square = x => x * x;
Action<string> print = msg => Console.WriteLine(msg);

// 多行
Func<int, int> complex = x =>
{
    int y = x * 2;
    return y + 1;
};

13.4 事件 Event

事件是「特殊的委派」，用 event 關鍵字標記，類似 JS 的 EventEmitter 模式：

C#

public class Button
{
    public event Action OnClick;  // 宣告事件

    public void Click()
    {
        OnClick?.Invoke();  // 觸發事件
    }
}

var btn = new Button();
btn.OnClick += () => Console.WriteLine("被點了");  // 訂閱
btn.OnClick += () => Console.WriteLine("又一個處理器");
btn.Click();  // 兩個都會被呼叫

事件在 Windows Forms、WPF 桌面應用程式（包括很多 ERP 系統的前端）裡到處都是——按鈕、選單、所有 UI 互動都是事件驅動的。

Chapter 14非同步 async/await

你會 JS 的 async/await，C# 用起來幾乎一樣，但理解原理還是值得。

14.1 為什麼需要非同步

讀檔、查 DB、呼叫 API 這些 I/O 操作很慢。如果同步等待，整條執行緒會卡住——UI 應用會凍結、伺服器會無法回應其他請求。非同步讓 CPU 在等待時去做別的事。

14.2 基本用法

C#

// 定義非同步方法（回傳型別包 Task）
public async Task<string> FetchDataAsync(string url)
{
    using var client = new HttpClient();
    string result = await client.GetStringAsync(url);
    return result;
}

// 呼叫
string data = await FetchDataAsync("https://...");

// 沒回傳值的非同步方法
public async Task SaveAsync()
{
    await File.WriteAllTextAsync("path", "data");
}

14.3 跟 JS 的對照

JSC#
Promise<T>Task<T>
Promise<void>Task
async functionasync 修飾子
await promiseawait task
Promise.all([...])Task.WhenAll(...)
Promise.race([...])Task.WhenAny(...)

14.4 並行執行

C#

// 序列：總時間 = T1 + T2
var a = await FetchDataAsync(url1);
var b = await FetchDataAsync(url2);

// 並行：總時間 = max(T1, T2)
var taskA = FetchDataAsync(url1);
var taskB = FetchDataAsync(url2);
await Task.WhenAll(taskA, taskB);
var a = taskA.Result;
var b = taskB.Result;
命名慣例

非同步方法慣例上加 Async 後綴：SaveAsync、FetchDataAsync。看到名字就知道要 await。.NET 標準函式庫所有非同步版本都遵循這慣例。

Chapter 16入職前的最後叮嚀

把這些放心裡，你進去做 ERP 會適應得快很多。

16.1 你已經會的、會的

從 JS 過來，這些東西你幾乎免費獲得：

  • 變數、運算子、流程控制（if/for/while）的概念
  • 函式/方法的基本用法
  • 陣列、迴圈、字串操作的直覺
  • async/await（語法幾乎一樣）
  • Lambda 表達式（就是箭頭函式）
  • LINQ 大部分方法（就是 array methods）

16.2 真正要花力氣的

  • 型別系統的紀律——什麼都要先想型別。剛開始會卡，習慣之後反而會喜歡（編譯期幫你抓 bug）
  • 值型別 vs 參考型別——這個直覺要建立起來，賦值、傳參數的行為都跟它有關
  • 物件導向的思維——一切都在類別裡，習慣把功能「封裝」成類別
  • 例外處理的階層——熟悉常見例外型別，知道什麼時候該 catch、什麼時候該 throw
  • using / IDisposable——DB 連線、檔案、Stream 都要記得釋放

16.3 你進公司會看到的東西（先預習名詞）

  • ADO.NET：.NET 連 SQL 資料庫的基礎 API（SqlConnection、SqlCommand、SqlDataReader）
  • Entity Framework：ORM，用物件操作 DB，LINQ 直接查 DB
  • Windows Forms / WPF：桌面應用框架。Forms 是老牌、簡單；WPF 較新、用 XAML
  • NuGet：套件管理器，類似 npm
  • Visual Studio：主流 IDE，比 VS Code 更完整。會用 VS 是基本技能
  • PowerBuilder 整合：公司的特殊狀況。PowerBuilder 多半透過 COM 或 .dll 跟 C# 互動，你需要的時候再學

16.4 學習節奏建議

  1. 第一週：讀完這份筆記、跑幾個小程式（Hello World、計算機、簡單的類別練習）
  2. 到職前：寫一個小專案（如待辦清單），讓自己摸過類別、List、檔案讀寫、try/catch
  3. 到職第一個月：別急著精通，先讀懂同事的程式碼。看到不懂的關鍵字就查，記下來
  4. 到職後二到三個月：開始能改簡單功能、寫小模組。這時候再回來找我，我幫你做「進階補強」

16.5 一句總結

JS 是「先寫再說，錯了再修」；C# 是「先想清楚，編譯期就抓錯」。前者適合快速迭代的前端，後者適合穩定可靠的企業系統。你不是在學一個更難的語言，是在學一種更嚴謹的思維方式——這正是 ERP 領域需要的。
