C# vs JavaScript

給 JS 開發者的 C# 完整筆記

你已經會 JS，C# 的概念大部分都類似。這份筆記每個概念都會對照 JS，讓你快速建立連結

C# 是什麼？

C# 是微軟開發的強型別、編譯式、物件導向語言，主要用於後端 API、桌面應用、遊戲（Unity）開發。搭配 .NET 平台運行，是企業系統最常見的語言之一。

最大的心態差異

概念JavaScriptC#
型別系統動態型別，執行時才知道型別靜態型別，寫的時候就要指定型別
執行方式解譯式（直接執行）編譯式（先編譯成 IL，再執行）
錯誤時機很多錯誤在執行時才發現大部分錯誤在編譯時就抓到
函數/方法一等公民，可以隨意傳遞通常屬於某個類別
null到處都是 null/undefined有 null 安全機制，可以避免 NullReferenceException
分號可選必填
縮排建議用建議用（不影響編譯）
🟡 JS 開發者的優勢 你已經懂 async/await、箭頭函數、陣列方法（map/filter/reduce）、物件導向概念。C# 的對應功能幾乎都存在，只是語法不同。學習曲線比你想像的低很多。

Hello World — 為什麼 C# 要寫這麼多行？

先看傳統寫法（你在很多教學文件會看到的），每一行都有它存在的理由：

🟣 C# 傳統寫法
using System; class Program { static void Main() { Console.WriteLine("Hello, World!"); } }
🟡 JavaScript
console.log("Hello, World!");

逐行拆解

using System;
這行在做什麼

System 是 C# 的標準函式庫命名空間，裡面有 Console、Math、DateTime 等常用工具。using 就是「我要使用這個命名空間裡的東西」。

JS 對應概念

就像 JS 的 import，只是 C# 這裡是 import「一整個命名空間」而不是單一模組。沒寫這行的話，每次用 Console 都要打完整路徑 System.Console.WriteLine()。

class Program
這行在做什麼

C# 所有的程式碼必須存在於某個類別裡，不能像 JS 那樣直接在頂層寫邏輯。Program 只是這個類別的名字，你可以叫它任何名字。

JS 對應概念

JS 不需要這個，因為 JS 允許「模組頂層程式碼」。但你在寫 React/Vue 組件時其實也是在定義 class 或 function，只是語言不強制而已。

static void Main()
這行在做什麼

這是程式的進入點，相當於「程式從這裡開始跑」。拆開來看：

  • static — 不需要建立物件就能呼叫（類別直接呼叫）
  • void — 這個方法沒有回傳值
  • Main — 這個名字是固定的，.NET 執行環境會找這個方法當入口
JS 對應概念

就像 Node.js 直接從檔案頂層開始執行。C# 需要你明確指定「從哪個方法開始」，而 .NET 規定這個方法一定要叫 Main。

Console.WriteLine("Hello, World!");
這行在做什麼

Console 是 System 命名空間裡的類別，WriteLine 是它的方法，會輸出文字並換行。結尾的分號是必填的，每個陳述式（statement）都要加。

JS 對應概念

console.log() — 幾乎一模一樣，只是 C# 的 C 是大寫（因為 Console 是類別名稱）。

{ } （大括號）
這行在做什麼

C# 用大括號 { } 表示程式碼區塊的開始和結束。類別有一對，方法裡面又有一對，所以你看到很多層縮排。

JS 對應概念

和 JS 的 { } 完全一樣，只是 C# 的每個 if、for、class、method 都必須用大括號，不能像 JS 那樣省略單行的括號。

現代 C# 的解法 — 頂層語句（Top-level statements）

C# 9 之後加入了「頂層語句」，讓你不用寫 class 和 Main，小程式直接這樣寫就好：

🟣 現代 C#（頂層語句）
// Program.cs — 這樣就夠了！ Console.WriteLine("Hello, World!"); // 完全不需要 using、class、Main // .NET 幫你自動包一層
🟡 JavaScript
console.log("Hello, World!"); // 一樣簡潔！
💡 所以為什麼教學還是寫傳統的？ 因為大型專案的程式碼都是傳統寫法 — 有 class、有 Main、有多個方法。頂層語句只適合程式入口（Program.cs），其他檔案還是要寫 class。所以兩種都要認識，但實際開發中你只有在 Program.cs 才會用頂層語句。

C# 最大的特色就是強型別，每個變數都必須有明確的型別

基本型別對照

C# 型別說明JS 對應範例
int整數（-21億 ~ 21億）Number42
long大整數BigInt1234567890L
double浮點數（預設）Number3.14
float單精度浮點數Number3.14f
decimal高精度小數（金額用）無直接對應9.99m

值型別 vs 參考型別

這是 C# 很重要的概念，JS 中也有類似的概念（primitive vs object）：

🟣 值型別（Value Type）
// int, bool, double, char, struct // 複製時是複製值本身 int a = 5; int b = a; // b 是 a 的複製 b = 10; Console.WriteLine(a); // 還是 5
🟣 參考型別（Reference Type）
// class, string, array, List // 複製時是複製參考（記憶體位址） int[] a = { 1, 2, 3 }; int[] b = a; // b 指向同一個陣列 b[0] = 99; Console.WriteLine(a[0]); // 99！

可為 null 的型別（Nullable）

🟣 C#
// 值型別預設不能是 null int x = null; // ❌ 編譯錯誤 // 加 ? 才能是 null int? x = null; // ✅ string? name = null; // ✅ // 使用前要檢查 if (x is not null) { Console.WriteLine(x.Value); }
🟡 JavaScript
// JS 隨時都可以是 null/undefined let x = null; // 沒問題 let y; // undefined // 可選鏈 const name = user?.name;

變數宣告

C# 的變數宣告比 JS 更嚴格，但 var 讓它不那麼囉嗦

🟣 C# — 宣告方式
// 明確型別 int age = 25; string name = "Cooper"; bool isActive = true; double price = 9.99; // var — 型別推斷（編譯器自動判斷） var age = 25; // int var name = "Cooper"; // string var list = new List<int>(); // const — 編譯時常數（必須當場給值） const double PI = 3.14159; // readonly — 執行時常數（可在建構子賦值） readonly string id = Guid.NewGuid().ToString();
🟡 JavaScript
// let — 可重新賦值 let age = 25; let name = "Cooper"; // const — 不可重新賦值 const PI = 3.14159; // var — 不推薦（函數作用域） var old = "don't use"; // JS 不需要宣告型別 let x = 42; x = "now a string"; // 完全合法
💡 C# 的 var ≠ JS 的 var C# 的 var 是「型別推斷」，編譯器會幫你推斷型別，型別一旦確定就不能變。JS 的 var 是函數作用域、可重新賦值為任何型別。完全不同！C# 的 var 反而更像 JS 的 const（都是推斷後不能換型別）。

字串操作對比

🟣 C#
string name = "Cooper"; // 字串插值（最常用） string msg = $"Hello, {name}!"; // 多行字串（C# 11+） string html = """ <h1>Hello</h1> <p>World</p> """; // 常用方法 name.Length // 長度（是屬性不是方法） name.ToUpper() // 轉大寫 name.Contains("oo") // 包含 name.Replace("o","0")// 取代 name.Split(',') // 分割 name.Trim() // 去空白
🟡 JavaScript
const name = "Cooper"; // 模板字串 const msg = `Hello, ${name}!`; // 多行字串 const html = ` <h1>Hello</h1> <p>World</p> `; // 常用方法 name.length // 長度 name.toUpperCase() // 轉大寫 name.includes("oo") // 包含 name.replace("o","0") // 取代 name.split(',') // 分割 name.trim() // 去空白

運算子

大部分和 JS 一樣，但有幾個重要差異

比較運算子

🟣 C#
// C# 只有 == 和 != // 沒有 === 因為型別已經在宣告時確定 5 == 5 // true 5 == "5" // 編譯錯誤！不同型別不能比 string a = "hello"; string b = "hello"; a == b // true（string 比內容） // 物件比較（比參考） var x = new Person(); var y = new Person(); x == y // false（不同物件）
🟡 JavaScript
// JS 有 == 和 === 5 == "5" // true（隱式轉型）😱 5 === "5" // false（嚴格比較）✅ const a = "hello"; const b = "hello"; a === b // true const x = {}; const y = {}; x === y // false（不同參考）

C# 特有的運算子

    
🟣 C# 特有運算子

    
// ?? 空值合併（和 JS 一樣！）
string? name = null;
string display = name ?? "匿名";  // "匿名"

// ??= 空值賦值（C# 8+）
name ??= "預設值";  // 只有 null 時才賦值

// ?. 可選鏈（和 JS 完全一樣！）
int? len = user?.Name?.Length;

// is — 型別判斷（比 typeof 強）
if (obj is string s)
{
    Console.WriteLine(s.Length); // s 自動是 string 型別
}

// as — 安全型別轉換（失敗回傳 null）
var s = obj as string;  // 不是 string 就是 null

// (type) — 強制型別轉換（失敗丟例外）
int x = (int)3.9;  // 3（截斷）

流程控制

if / switch / for / while / foreach — 大部分和 JS 一樣

🟣 C# — if / else
int score = 85; if (score >= 90) Console.WriteLine("A"); else if (score >= 80) Console.WriteLine("B"); else Console.WriteLine("C"); // 三元運算子（和 JS 一樣） string grade = score >= 60 ? "Pass" : "Fail";
🟡 JavaScript
const score = 85; if (score >= 90) { console.log("A"); } else if (score >= 80) { console.log("B"); } else { console.log("C"); } // 三元運算子 const grade = score >= 60 ? "Pass" : "Fail";

Switch — C# 更強大

🟣 C# switch expression（現代）
// switch expression（C# 8+，很簡潔） string grade = score switch { >= 90 => "A", >= 80 => "B", >= 70 => "C", _ => "F" // _ 是預設值（類似 default） }; // 型別匹配（JS 做不到） string desc = obj switch { int n => $"整數 {n}", string s => $"字串 {s}", null => "null", _ => "其他" };
🟡 JavaScript
// JS switch 不支援範圍比較 switch (true) { case score >= 90: return "A"; case score >= 80: return "B"; default: return "F"; } // 或用物件映射 const map = { A: 90, B: 80, C: 70 };

迴圈對比

🟣 C#
// for（和 JS 一樣） for (int i = 0; i < 5; i++) Console.WriteLine(i); // foreach（遍歷集合） int[] nums = { 1, 2, 3 }; foreach (int n in nums) Console.WriteLine(n); // while / do-while（和 JS 一樣） while (condition) { ... } do { ... } while (condition);
🟡 JavaScript
// for for (let i = 0; i < 5; i++) console.log(i); // for...of（類似 C# foreach） const nums = [1, 2, 3]; for (const n of nums) console.log(n); // forEach 方法 nums.forEach(n => console.log(n));

方法 (Method)

C# 叫「方法」不叫「函數」，通常屬於某個類別

🟣 C# 方法
// 回傳型別 方法名稱(參數型別 參數名) static int Add(int a, int b) { return a + b; } // void = 沒有回傳值 static void PrintHello(string name) { Console.WriteLine($"Hello, {name}!"); } // 預設參數 static string Greet(string name, string greeting = "Hello") => $"{greeting}, {name}!"; // 箭頭方法（單行） // 呼叫 Add(1, 2); Greet("Cooper"); Greet(name: "Cooper", greeting: "Hi"); // 具名參數
🟡 JavaScript
// 不需要宣告回傳型別 function add(a, b) { return a + b; } // 沒有 void，不 return 就是 undefined function printHello(name) { console.log(`Hello, ${name}!`); } // 預設參數 const greet = (name, greeting = "Hello") => `${greeting}, ${name}!`; // 呼叫 add(1, 2); greet("Cooper");

Lambda 表達式（C# 的箭頭函數）

🟣 C#
// Lambda 表達式 Func<int, int, int> add = (a, b) => a + b; Action<string> print = s => Console.WriteLine(s); Func<int, bool> isEven = n => n % 2 == 0; // Func = 有回傳值的函數型別 // Action = 沒有回傳值的函數型別 // Func<參數型別..., 回傳型別> // 傳入方法 var evens = numbers.Where(n => n % 2 == 0);
🟡 JavaScript
// 箭頭函數 const add = (a, b) => a + b; const print = s => console.log(s); const isEven = n => n % 2 === 0; // JS 函數是一等公民 // 隨時可以傳遞，不需要特別宣告型別 // 傳入方法 const evens = numbers.filter(n => n % 2 === 0);
中階

類別 & 物件

C# 是真正的 OOP 語言，類別的功能比 JS 更完整

🟣 C# 類別
public class Person { // 屬性（Properties） public string Name { get; set; } public int Age { get; private set; } // 外部唯讀 // 建構子 public Person(string name, int age) { Name = name; Age = age; } // 方法 public string Greet() => $"Hi, I'm {Name}, {Age} years old."; } // 使用 var p = new Person("Cooper", 25); Console.WriteLine(p.Greet()); Console.WriteLine(p.Name);
🟡 JavaScript
class Person { // 屬性 #age; // private field // 建構子 constructor(name, age) { this.name = name; this.#age = age; } // getter get age() { return this.#age; } // 方法 greet() { return `Hi, I'm ${this.name}`; } } // 使用 const p = new Person("Cooper", 25); console.log(p.greet()); console.log(p.name);

存取修飾詞

修飾詞說明JS 對應
public任何地方都能存取一般屬性
private只有類別內部可存取#name（private field）
protected類別本身 + 子類別無直接對應
internal同一個組件（專案）內無直接對應

Record — 現代 C# 的不可變資料類別

🟣 C# record
// 一行定義資料類別（C# 9+） public record Point(int X, int Y); var p1 = new Point(1, 2); var p2 = p1 with { X = 10 }; // 複製並改 X p1 == p2 // false（值不同） var p3 = new Point(1, 2); p1 == p3 // true（值相同就相等）
🟡 JavaScript 類似概念
// JS 沒有 record，通常用物件 const p1 = { x: 1, y: 2 }; // 複製並修改 const p2 = { ...p1, x: 10 }; // JS 物件比較的是參考 p1 === p2 // false（不同物件） // 即使值一樣也是 false！
中階

OOP 三大特性

封裝、繼承、多型 — C# 比 JS 更嚴謹的物件導向

① 封裝（Encapsulation）

封裝的概念是：把資料（欄位）藏起來，只透過公開的介面（屬性/方法）讓外界存取。這樣可以控制「誰能讀、誰能寫」，避免資料被意外改壞。

🟣 C# — 封裝
public class BankAccount { // private 欄位 — 外部完全看不到 private decimal _balance = 0; // public 屬性 — 外部只能讀，不能直接改 public decimal Balance => _balance; // 透過方法控制存款邏輯 public void Deposit(decimal amount) { if (amount <= 0) throw new ArgumentException("金額必須大於 0"); _balance += amount; } public void Withdraw(decimal amount) { if (amount > _balance) throw new InvalidOperationException("餘額不足"); _balance -= amount; } } var acc = new BankAccount(); acc.Deposit(1000); Console.WriteLine(acc.Balance); // 1000 acc._balance = 9999; // ❌ 編譯錯誤！private 不能直接存取
🟡 JavaScript
class BankAccount { // # 前綴 = private（ES2022） #balance = 0; // getter 讓外部只能讀 get balance() { return this.#balance; } deposit(amount) { if (amount <= 0) throw new Error("金額必須大於 0"); this.#balance += amount; } withdraw(amount) { if (amount > this.#balance) throw new Error("餘額不足"); this.#balance -= amount; } } const acc = new BankAccount(); acc.deposit(1000); console.log(acc.balance); // 1000 acc.#balance = 9999; // ❌ SyntaxError
💡 C# 的 { get; set; } 是什麼？ 這是「自動屬性」，背後 C# 會自動建一個 private 欄位幫你存值。
public string Name { get; set; } — 外部可讀可寫
public string Name { get; private set; } — 外部只能讀，類別內部才能寫
public string Name { get; } — 唯讀，只能在建構子賦值

② 繼承（Inheritance）

子類別繼承父類別的屬性和方法，達到程式碼複用。C# 一個類別只能繼承一個父類別（和 JS 一樣），但可以實作多個 Interface。

🟣 C#
public class Animal { public string Name { get; set; } // virtual = 允許子類別覆寫 public virtual void Speak() => Console.WriteLine("..."); } // : Animal 代表繼承 Animal public class Dog : Animal { // override = 覆寫父類別的 virtual 方法 public override void Speak() => Console.WriteLine("Woof!"); // 子類別自己的方法 public void Fetch() => Console.WriteLine("*撿球*"); } var d = new Dog { Name = "Rex" }; d.Speak(); // "Woof!"（覆寫後的版本） d.Fetch(); // "*撿球*" Console.WriteLine(d.Name); // "Rex"（繼承自 Animal）
🟡 JavaScript
class Animal { constructor(name) { this.name = name; } // JS 方法預設就可以被覆寫 // 不需要 virtual 關鍵字 speak() { console.log("..."); } } // extends 代表繼承 class Dog extends Animal { // 直接覆寫，不需要 override speak() { console.log("Woof!"); } fetch() { console.log("*撿球*"); } } const d = new Dog("Rex"); d.speak(); d.fetch(); console.log(d.name);

base — 呼叫父類別

🟣 C# — base
public class Cat : Animal { public int Lives { get; } // base(...) 呼叫父類別建構子 public Cat(string name, int lives) : base(name) { Lives = lives; } public override void Speak() { base.Speak(); // 先執行父類別的版本 Console.WriteLine("Meow!"); } }
🟡 JavaScript — super
class Cat extends Animal { constructor(name, lives) { super(name); // 呼叫父類別建構子 this.lives = lives; } speak() { super.speak(); // 先執行父類別版本 console.log("Meow!"); } }

③ 多型（Polymorphism）

多型的意思是：同一個型別的變數，可以在執行時指向不同的子類別物件，並呼叫各自的版本。這讓你可以寫「通用的程式碼」，不需要一堆 if/else 判斷型別。

🟣 C# — 多型
// 用父類別型別裝不同的子類別 Animal a1 = new Dog(); Animal a2 = new Cat("Kitty", 9); Animal a3 = new Animal(); var animals = new List<Animal> { a1, a2, a3 }; // 同樣呼叫 Speak()，但實際執行各自的版本 foreach (var animal in animals) { animal.Speak(); // Dog → "Woof!" // Cat → "..." 然後 "Meow!" // Animal → "..." } // 不需要這樣寫： // if (animal is Dog) ...dog stuff // if (animal is Cat) ...cat stuff
🟡 JavaScript
// JS 也有多型，只是沒有型別約束 const animals = [ new Dog("Rex"), new Cat("Kitty"), new Animal("?"), ]; // 一樣呼叫 speak()，執行各自的版本 for (const animal of animals) { animal.speak(); } // JS 不需要宣告型別 // 只要物件有 speak() 就能呼叫 // （Duck Typing）
💡 C# 多型 vs JS Duck Typing JS 的「多型」其實是 Duck Typing：「只要物件有這個方法，就能呼叫」，不在乎它是什麼類別。C# 的多型更嚴謹：變數必須是同一個父類別型別，執行時才決定呼叫哪個子類別的版本。C# 這樣做的好處是型別安全 — 你絕對不會意外傳進一個沒有 Speak() 的物件。

Interface — 多型的另一種形式

Interface 定義「合約」：任何實作這個 Interface 的類別，都保證有這些方法。這讓多型可以跨越繼承階層。

🟣 C# Interface
// 定義合約 — 名稱慣例以 I 開頭 public interface ISpeakable { void Speak(); string Name { get; } } // 任何類別都可以實作，不需要繼承同一個父類別 public class Robot : ISpeakable { public string Name => "R2D2"; public void Speak() => Console.WriteLine("Beep boop!"); } // Robot 和 Dog 完全不同繼承體系 // 但都能放進 ISpeakable 的 List var speakers = new List<ISpeakable> { new Dog(), new Cat("Kitty", 9), new Robot() }; foreach (var s in speakers) s.Speak(); // 各自執行自己的版本
🟡 和 TypeScript 的對比 TypeScript 的 interface 和 C# 很像，但有一個關鍵差異：C# 必須明確宣告「我實作了這個 interface」（class Dog : ISpeakable），TypeScript 是結構型別 — 只要你的物件形狀符合 interface 的定義，就自動算實作了，不需要明確宣告。

LINQ

Language Integrated Query — C# 版的 Array 方法，功能更強大

如果你用過 JS 的 .filter() .map() .reduce()，LINQ 就是 C# 版本，而且更強大。

🟣 C# LINQ
var numbers = new List<int> { 1,2,3,4,5,6 }; // Where = filter var evens = numbers.Where(n => n % 2 == 0); // [2, 4, 6] // Select = map var doubled = numbers.Select(n => n * 2); // [2, 4, 6, 8, 10, 12] // Aggregate = reduce var sum = numbers.Aggregate(0, (acc, n) => acc + n); // 直接用 Sum(), Count(), Min(), Max(), Average() var total = numbers.Sum(); var avg = numbers.Average(); // 鏈式（和 JS 一樣） var result = numbers .Where(n => n > 2) .Select(n => n * 10) .OrderByDescending(n => n) .Take(3) // 取前 3 個 .ToList(); // 轉成 List
🟡 JavaScript
const numbers = [1,2,3,4,5,6]; // filter const evens = numbers.filter(n => n % 2 === 0); // [2, 4, 6] // map const doubled = numbers.map(n => n * 2); // [2, 4, 6, 8, 10, 12] // reduce const sum = numbers.reduce((acc, n) => acc + n, 0); // 沒有內建 Sum/Average // 需要自己 reduce 或用工具庫 // 鏈式 const result = numbers .filter(n => n > 2) .map(n => n * 10) .sort((a, b) => b - a) .slice(0, 3);

Async & Await

C# 的 async/await 和 JS 幾乎一樣！這是最容易上手的部分

✅ 好消息 C# 的 async/await 概念和 JS 幾乎完全相同！唯一的差別是 C# 用 Task 代替 JS 的 Promise，其他語法幾乎一致。
🟣 C# async/await
// Task = Promise // Task<T> = Promise<T>（有回傳值） public async Task<string> FetchUserAsync(int id) { using var client = new HttpClient(); var response = await client.GetStringAsync( $"https://api.example.com/users/{id}" ); return response; } // 呼叫 var user = await FetchUserAsync(1); // 沒有回傳值用 Task（不是 Task<T>） public async Task SaveAsync(User user) { await _db.SaveChangesAsync(); } // 並行執行（類似 Promise.all） var t1 = FetchUserAsync(1); var t2 = FetchUserAsync(2); var results = await Task.WhenAll(t1, t2);
🟡 JavaScript
// Promise = Task async function fetchUser(id) { const response = await fetch( `https://api.example.com/users/${id}` ); return response.json(); } // 呼叫 const user = await fetchUser(1); // 沒有回傳值就不寫回傳型別 async function save(user) { await db.save(user); } // 並行（Promise.all） const [u1, u2] = await Promise.all([ fetchUser(1), fetchUser(2) ]);

🟣 C#
