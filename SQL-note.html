什麼是 SQL？

SQL（Structured Query Language）是用來與關聯式資料庫溝通的語言。透過 SQL 你可以建立表格、查詢資料、新增修改刪除記錄，幾乎所有系統的後端都會用到。

CREATE TABLE

CREATE TABLE users (
  id         BIGSERIAL    PRIMARY KEY,          -- 自動遞增主鍵
  username   VARCHAR(50)  NOT NULL UNIQUE,       -- 不可空、唯一
  email      VARCHAR(255) NOT NULL UNIQUE,
  age        INT          CHECK (age >= 0),       -- 約束條件
  role       VARCHAR(20)  DEFAULT 'user',        -- 預設值
  created_at TIMESTAMP    DEFAULT NOW()          -- 自動記錄建立時間
);

CREATE TABLE posts (
  id         BIGSERIAL PRIMARY KEY,
  user_id    BIGINT NOT NULL,
  title      VARCHAR(200) NOT NULL,
  content    TEXT,
  created_at TIMESTAMP DEFAULT NOW(),

  -- 外鍵：posts.user_id 連結到 users.id
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
SQL
💡 ON DELETE 選項 CASCADE — 刪除父記錄時，子記錄一起刪除
SET NULL — 子記錄的外鍵欄位設為 NULL
RESTRICT — 有子記錄時禁止刪除父記錄（預設）

ALTER TABLE — 修改表格

-- 新增欄位
ALTER TABLE users ADD COLUMN avatar_url TEXT;

-- 修改欄位型別
ALTER TABLE users ALTER COLUMN age TYPE SMALLINT;

-- 重新命名欄位
ALTER TABLE users RENAME COLUMN username TO name;

-- 刪除欄位
ALTER TABLE users DROP COLUMN age;

-- 新增約束
ALTER TABLE users ADD CONSTRAINT chk_age CHECK (age >= 18);
SQL

DROP & TRUNCATE

-- 刪除整張表（結構也刪掉）
DROP TABLE users;
DROP TABLE IF EXISTS users;  -- 安全寫法，不存在也不報錯

-- 清空所有資料（保留結構，比 DELETE 快）
TRUNCATE TABLE users;
TRUNCATE TABLE users RESTART IDENTITY;  -- 同時重置自動遞增 ID
SQL
入門

SELECT 查詢

SQL 最核心的語句，取出你需要的資料

基本語法

-- 取所有欄位（* 在正式環境不建議用）
SELECT * FROM users;

-- 指定欄位
SELECT id, username, email FROM users;

-- 欄位別名（AS）
SELECT
  username   AS name,
  email      AS mail,
  created_at AS joined
FROM users;

-- 計算欄位
SELECT
  name,
  price,
  quantity,
  price * quantity AS total
FROM order_items;

-- 去除重複（DISTINCT）
SELECT DISTINCT country FROM users;
SQL

SELECT 執行順序

SQL 語句的撰寫順序和執行順序不一樣，這是很多人搞混的地方：

執行順序語句說明
1FROM / JOIN先確定資料來源
2WHERE過濾原始資料列
3GROUP BY分組
4HAVING過濾分組後結果
5SELECT選取欄位、計算
6DISTINCT去重
7ORDER BY排序
8LIMIT / OFFSET分頁
⚠️ 常見錯誤 WHERE 比 SELECT 先執行，所以 WHERE 裡不能用 SELECT 定義的別名！
SELECT price * qty AS total FROM orders WHERE total > 100 ← 錯誤
改用 WHERE price * qty > 100 或用子查詢包起來。
入門

WHERE 過濾

條件篩選：比較、邏輯、模糊搜尋、NULL 判斷

比較與邏輯運算子

-- 比較運算子
SELECT * FROM users WHERE age =  25;
SELECT * FROM users WHERE age != 25;   -- 或 <>
SELECT * FROM users WHERE age >  18;
SELECT * FROM users WHERE age >= 18;

-- 邏輯運算子
SELECT * FROM users
WHERE age >= 18 AND role = 'admin';

SELECT * FROM users
WHERE role = 'admin' OR role = 'editor';

SELECT * FROM users
WHERE NOT is_banned;
SQL

IN、BETWEEN、LIKE、IS NULL

-- IN：符合清單中的任一值
SELECT * FROM users
WHERE role IN ('admin', 'editor', 'moderator');

-- BETWEEN：範圍（含兩端）
SELECT * FROM orders
WHERE created_at BETWEEN '2024-01-01' AND '2024-12-31';

-- LIKE：模糊搜尋
-- % 代表任意長度字串，_ 代表單一字元
SELECT * FROM users WHERE email LIKE '%@gmail.com';
SELECT * FROM users WHERE username LIKE 'A%';      -- 以 A 開頭
SELECT * FROM users WHERE username LIKE 'A___';    -- A 開頭共 4 字元

-- IS NULL / IS NOT NULL
SELECT * FROM users WHERE avatar_url IS NULL;
SELECT * FROM users WHERE avatar_url IS NOT NULL;

-- ⚠️ NULL 不能用 = 判斷！
-- WHERE avatar_url = NULL  ← 永遠不成立
SQL

DML 資料操作

INSERT、UPDATE、DELETE — 新增、修改、刪除資料

INSERT — 新增資料

-- 新增單筆
INSERT INTO users (username, email, role)
VALUES ('alice', 'alice@example.com', 'admin');

-- 新增多筆
INSERT INTO users (username, email)
VALUES
  ('bob',   'bob@example.com'),
  ('carol', 'carol@example.com'),
  ('dave',  'dave@example.com');

-- INSERT ... RETURNING（PostgreSQL）— 取得新增後的資料
INSERT INTO users (username, email)
VALUES ('eve', 'eve@example.com')
RETURNING id, created_at;

-- UPSERT — 存在就更新，不存在就新增
INSERT INTO users (email, username)
VALUES ('alice@example.com', 'alice_new')
ON CONFLICT (email)
DO UPDATE SET username = EXCLUDED.username;
SQL

UPDATE — 更新資料

-- 更新單一欄位
UPDATE users
SET role = 'admin'
WHERE id = 1;

-- 更新多個欄位
UPDATE users
SET
  username   = 'alice_updated',
  updated_at = NOW()
WHERE id = 1;

-- ⚠️ 沒有 WHERE 會更新全部！永遠記得加 WHERE
SQL

DELETE — 刪除資料

-- 刪除指定條件
DELETE FROM users WHERE id = 1;

-- 刪除多筆
DELETE FROM users
WHERE created_at < '2020-01-01';

-- ⚠️ 沒有 WHERE = 刪除全部資料！
-- 建議先用 SELECT 確認要刪的資料再執行
SQL

INNER JOIN

只回傳兩表都有對應的資料（交集）

🔵⬜

LEFT JOIN

保留左表所有資料，右表沒有就 NULL

⬜🟡

RIGHT JOIN

保留右表所有資料，左表沒有就 NULL

🔵🟡🟣

FULL OUTER JOIN

保留兩表所有資料（聯集）

JOIN 語法與結果

-- INNER JOIN：只有 Alice、Bob（Carol 沒有 dept_id）
SELECT u.name, d.name AS dept
FROM users u
INNER JOIN departments d ON u.dept_id = d.id;
-- 結果：Alice/工程部、Bob/設計部

-- LEFT JOIN：三人都出現，Carol 的 dept 是 NULL
SELECT u.name, d.name AS dept
FROM users u
LEFT JOIN departments d ON u.dept_id = d.id;
-- 結果：Alice/工程部、Bob/設計部、Carol/NULL

-- 三張表連接
SELECT
  u.name        AS user_name,
  d.name        AS dept_name,
  p.title       AS post_title
FROM       users       u
LEFT JOIN  departments d ON u.dept_id = d.id
LEFT JOIN  posts       p ON p.user_id = u.id;
SQL
💡 實務建議 90% 的情況用 LEFT JOIN 就夠了。INNER JOIN 用在「沒有對應就不需要顯示」的情況，例如只顯示有部門的員工。

聚合 & GROUP BY

統計分析的核心：計數、加總、平均、分組

聚合函數

SELECT
  COUNT(*)           AS total_users,     -- 總筆數（含 NULL）
  COUNT(avatar_url) AS has_avatar,      -- 非 NULL 的筆數
  COUNT(DISTINCT country) AS countries, -- 不重複的國家數
  SUM(balance)       AS total_balance,  -- 加總
  AVG(age)           AS avg_age,         -- 平均
  MAX(age)           AS oldest,          -- 最大值
  MIN(age)           AS youngest         -- 最小值
FROM users;
SQL

GROUP BY — 分組統計

-- 每個部門有幾個人
SELECT
  dept_id,
  COUNT(*) AS member_count
FROM users
GROUP BY dept_id;

-- 結合 JOIN，顯示部門名稱
SELECT
  d.name        AS dept,
  COUNT(u.id) AS count,
  AVG(u.salary)  AS avg_salary
FROM       departments d
LEFT JOIN  users       u ON u.dept_id = d.id
GROUP BY   d.id, d.name
ORDER BY   avg_salary DESC;
SQL

HAVING — 過濾分組結果

-- 只顯示人數超過 3 人的部門
SELECT
  dept_id,
  COUNT(*) AS count
FROM users
GROUP BY dept_id
HAVING COUNT(*) > 3;

-- WHERE vs HAVING
-- WHERE  = 分組前過濾（作用在原始資料列）
-- HAVING = 分組後過濾（作用在聚合結果）
SELECT dept_id, COUNT(*) AS count
FROM users
WHERE  role != 'guest'      -- 先過濾掉 guest
GROUP BY dept_id
HAVING COUNT(*) > 2;        -- 再過濾人數
SQL

子查詢

查詢中的查詢，用來解決複雜的多步驟問題

WHERE 中的子查詢

-- 找出薪資高於平均的員工
SELECT name, salary
FROM employees
WHERE salary > (
  SELECT AVG(salary) FROM employees
);

-- IN 子查詢
SELECT * FROM users
WHERE id IN (
  SELECT user_id FROM posts
  WHERE created_at > '2024-01-01'
);

-- EXISTS：有沒有符合的記錄（效能通常比 IN 好）
SELECT * FROM users u
WHERE EXISTS (
  SELECT 1 FROM posts p
  WHERE p.user_id = u.id
);
SQL

FROM 中的子查詢（衍生表）

-- 先統計再過濾（解決 WHERE 不能用別名的問題）
SELECT *
FROM (
  SELECT
    dept_id,
    COUNT(*)        AS count,
    AVG(salary)   AS avg_sal
  FROM employees
  GROUP BY dept_id
) AS dept_stats
WHERE avg_sal > 50000;  -- 這裡可以用別名了！
SQL

SELECT 中的子查詢（相關子查詢）

-- 每個用戶的文章數（相關子查詢，每行都執行一次，效能較差）
SELECT
  name,
  (SELECT COUNT(*) FROM posts WHERE user_id = u.id) AS post_count
FROM users u;

-- 建議改用 LEFT JOIN + COUNT（效能更好）
SELECT u.name, COUNT(p.id) AS post_count
FROM users u
LEFT JOIN posts p ON p.user_id = u.id
GROUP BY u.id, u.name;
SQL

排序 & 分頁

ORDER BY、LIMIT、OFFSET — 控制結果順序與數量

ORDER BY

-- 單一欄位排序
SELECT * FROM users ORDER BY created_at DESC;  -- 新到舊
SELECT * FROM users ORDER BY name ASC;          -- A-Z（預設）

-- 多欄位排序
SELECT * FROM users
ORDER BY dept_id ASC, salary DESC;  -- 先按部門升序，同部門再按薪資降序

-- NULL 排序（PostgreSQL）
ORDER BY score DESC NULLS LAST;   -- NULL 排在最後
ORDER BY score ASC  NULLS FIRST;  -- NULL 排在最前
SQL

LIMIT & OFFSET — 分頁

-- 取前 10 筆
SELECT * FROM posts
ORDER BY created_at DESC
LIMIT 10;

-- 分頁查詢（第 N 頁，每頁 10 筆）
SELECT * FROM posts
ORDER BY created_at DESC
LIMIT  10                    -- 每頁筆數
OFFSET (page - 1) * 10;     -- 跳過前幾筆

-- 第 1 頁：OFFSET 0
-- 第 2 頁：OFFSET 10
-- 第 3 頁：OFFSET 20
SQL
⚠️ OFFSET 分頁的效能問題 資料量大時（百萬筆以上），OFFSET 越大效能越差，因為資料庫仍需掃描跳過的資料。大型應用建議改用 Cursor-based 分頁，用 WHERE id > last_id LIMIT 10 取代 OFFSET。

內建函數

字串、數字、日期、條件函數

字串函數

SELECT
  LENGTH(name),                         -- 字串長度
  UPPER(name),                          -- 轉大寫
  LOWER(email),                         -- 轉小寫
  TRIM(name),                           -- 去掉首尾空白
  SUBSTRING(name, 1, 3),              -- 取前 3 個字元
  CONCAT(first_name, ' ', last_name),  -- 字串串接
  first_name || ' ' || last_name,      -- 串接（PostgreSQL 縮寫）
  REPLACE(bio, '舊詞', '新詞'),         -- 取代字串
  SPLIT_PART(email, '@', 1)            -- 以 @ 分割取第 1 部分
FROM users;
SQL

數字函數

SELECT
  ROUND(price, 2),    -- 四捨五入到小數點後 2 位
  CEIL(price),        -- 無條件進位
  FLOOR(price),       -- 無條件捨去
  ABS(balance),       -- 絕對值
  MOD(id, 2),         -- 取餘數（奇偶判斷）
  POWER(x, 2)         -- 次方
FROM products;
SQL

日期函數

SELECT
  NOW(),                               -- 當前時間（含時區）
  CURRENT_DATE,                        -- 今天日期
  DATE_PART('year',  created_at),    -- 取年份
  DATE_PART('month', created_at),    -- 取月份
  DATE_TRUNC('month', created_at),   -- 截斷到月份開始
  AGE(birth_date),                    -- 計算年齡
  created_at + INTERVAL '7 days',   -- 加 7 天
  created_at - INTERVAL '1 month'   -- 減 1 個月
FROM users;
SQL

視窗函數

在保留所有列的同時進行聚合計算，是 SQL 最強大的特性之一

視窗函數與 GROUP BY 的最大差異：GROUP BY 會將多列合併成一列，視窗函數保留每一列，同時附加計算結果。

基本語法

函數名稱() OVER (
  PARTITION BY 分組欄位   -- 可選：按哪個欄位分組
  ORDER BY     排序欄位   -- 可選：視窗內的排序
)
SQL

排名函數

SELECT
  name,
  dept_id,
  salary,

  -- ROW_NUMBER：每列唯一序號
  ROW_NUMBER() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS row_num,

  -- RANK：同分同名次，下一名跳號（1,1,3）
  RANK()       OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rank,

  -- DENSE_RANK：同分同名次，不跳號（1,1,2）
  DENSE_RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS dense_rank

FROM employees;
SQL

實用範例 — 取每個部門薪資最高的員工

-- 先用視窗函數加上排名
SELECT *
FROM (
  SELECT
    name, dept_id, salary,
    ROW_NUMBER() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rn
  FROM employees
) AS ranked
WHERE rn = 1;  -- 只取每部門第一名
SQL

累計與移動計算

SELECT
  date,
  revenue,

  -- 累計加總
  SUM(revenue) OVER (ORDER BY date) AS running_total,

  -- 移動平均（前後各 2 筆）
  AVG(revenue) OVER (
    ORDER BY date
    ROWS BETWEEN 2 PRECEDING AND 2 FOLLOWING
  ) AS moving_avg,

  -- 前一列的值（LAG）
  LAG(revenue, 1) OVER (ORDER BY date) AS prev_revenue,

  -- 後一列的值（LEAD）
  LEAD(revenue, 1) OVER (ORDER BY date) AS next_revenue

FROM daily_sales;
SQL

CTE & 遞迴查詢

WITH 語句讓複雜查詢變成可讀的積木組合

CTE（Common Table Expression）

-- 基本 CTE：先定義「暫時命名的查詢」，再使用
WITH active_users AS (
  SELECT * FROM users
  WHERE last_login > NOW() - INTERVAL '30 days'
),
user_post_counts AS (
  SELECT user_id, COUNT(*) AS post_count
  FROM posts
  GROUP BY user_id
)

-- 主查詢使用上面定義的 CTE
SELECT
  u.name,
  u.email,
  COALESCE(c.post_count, 0) AS posts
FROM      active_users     u
LEFT JOIN user_post_counts c ON c.user_id = u.id
ORDER BY posts DESC;
SQL

遞迴 CTE — 處理樹狀結構

-- 組織架構樹（每個員工有 manager_id 指向上司）
WITH RECURSIVE org_tree AS (
  -- 基礎案例：從最高層開始（沒有上司的人）
  SELECT id, name, manager_id, 0 AS level
  FROM employees
  WHERE manager_id IS NULL

  UNION ALL

  -- 遞迴案例：找每層的下屬
  SELECT e.id, e.name, e.manager_id, t.level + 1
  FROM employees e
  INNER JOIN org_tree t ON e.manager_id = t.id
)

SELECT
  REPEAT('  ', level) || name AS hierarchy,
  level
FROM org_tree
ORDER BY level, name;
SQL
💡 CTE vs 子查詢 功能上大多可以互換，但 CTE 可讀性更高，可以重複使用，適合拆解複雜查詢。子查詢在某些資料庫中效能更好，但可讀性差。

索引 & 效能

建對索引，查詢從秒級降到毫秒級

索引是什麼？

索引就像書本的目錄，讓資料庫不用掃描全表就能快速找到資料。代價是寫入變慢、佔用儲存空間。

建立索引

-- 基本索引
CREATE INDEX idx_users_email ON users(email);

-- 唯一索引（同時保證唯一性）
CREATE UNIQUE INDEX idx_users_username ON users(username);

-- 複合索引（順序很重要！）
CREATE INDEX idx_posts_user_date ON posts(user_id, created_at DESC);

-- 部分索引（只索引符合條件的資料）
CREATE INDEX idx_active_users ON users(email)
WHERE is_active = TRUE;

-- 刪除索引
DROP INDEX idx_users_email;
SQL

EXPLAIN — 查看查詢計畫

-- 看查詢計畫（不實際執行）
EXPLAIN
SELECT * FROM users WHERE email = 'alice@example.com';

-- 實際執行並顯示時間（ANALYZE）
EXPLAIN ANALYZE
SELECT * FROM users WHERE email = 'alice@example.com';

-- 看到 Seq Scan = 全表掃描 = 可能需要索引
-- 看到 Index Scan = 有用到索引 = 效能好
SQL

索引使用原則

適合建索引不適合建索引
常出現在 WHERE 的欄位很少用於查詢的欄位
JOIN 的連接欄位（外鍵）資料量少的表
ORDER BY 的欄位欄位值重複率高（如 boolean）
唯一性欄位（email、username）頻繁 INSERT/UPDATE 的表

交易 & ACID

確保多個操作「全部成功」或「全部失敗」，資料一致性的保障

ACID 特性

特性說明例子
Atomicity 原子性全部成功 or 全部失敗轉帳：扣款和入款要一起成功
Consistency 一致性交易前後資料必須合法帳戶餘額不能是負數
Isolation 隔離性交易互不干擾兩人同時轉帳，結果正確
Durability 持久性提交後永久保存斷電也不遺失

交易語法

-- 轉帳範例：A 轉 1000 給 B
BEGIN;  -- 開始交易

UPDATE accounts
SET balance = balance - 1000
WHERE id = 1;  -- A 扣款

UPDATE accounts
SET balance = balance + 1000
WHERE id = 2;  -- B 入款

COMMIT;  -- 確認提交（兩個操作都成功才到這）

-- 如果中間發生錯誤，回滾所有操作
ROLLBACK;

-- SAVEPOINT — 部分回滾
BEGIN;
UPDATE ... ;
SAVEPOINT step1;
UPDATE ... ;
ROLLBACK TO step1;  -- 只回滾到 step1
COMMIT;
SQL
💡 在 Supabase / ORM 中 使用 Supabase 的 rpc 或 Prisma 的 $transaction() 時，底層就是在幫你自動處理 BEGIN / COMMIT / ROLLBACK。理解交易概念有助於排查資料不一致的問題。

資料庫設計

正規化、關聯設計、常見模式

資料表關聯類型

關聯說明實作方式
一對一 (1:1)一個用戶有一個設定檔外鍵 + UNIQUE 約束
一對多 (1:N)一個用戶有多篇文章文章表加 user_id 外鍵
多對多 (M:N)文章有多個標籤，標籤有多篇文章中間關聯表（junction table）

多對多關聯設計

-- 文章與標籤的多對多關聯
CREATE TABLE posts (
  id    BIGSERIAL PRIMARY KEY,
  title VARCHAR(200) NOT NULL
);

CREATE TABLE tags (
  id   BIGSERIAL PRIMARY KEY,
  name VARCHAR(50) NOT NULL UNIQUE
);

-- 中間關聯表
CREATE TABLE post_tags (
  post_id BIGINT REFERENCES posts(id) ON DELETE CASCADE,
  tag_id  BIGINT REFERENCES tags(id)  ON DELETE CASCADE,
  PRIMARY KEY (post_id, tag_id)  -- 複合主鍵，防止重複
);

-- 查詢某篇文章的所有標籤
SELECT t.name
FROM       tags      t
INNER JOIN post_tags pt ON pt.tag_id  = t.id
WHERE pt.post_id = 1;
SQL

正規化原則（簡化版）

正規化規則
1NF每個欄位只存一個值（不存陣列）
2NF非主鍵欄位完全依賴主鍵
3NF非主鍵欄位不依賴其他非主鍵欄位
💡 實務上不需要過度正規化 正規化減少資料重複，但太多 JOIN 會影響效能。現代應用常用「適度反正規化」：把常一起查詢的資料放在同一張表，犧牲部分一致性換取查詢效能，例如把 username 存在 posts 表裡避免 JOIN。

常用設計 Checklist

  • 每張表都有主鍵（id）
  • 使用 created_at / updated_at 記錄時間戳
  • 外鍵欄位建立索引
  • 常查詢的欄位建立索引
  • VARCHAR 長度設合理上限（不要全部 TEXT）
  • NOT NULL 約束能加就加，確保資料完整性
  • 用軟刪除（is_deleted / deleted_at）而非直接 DELETE
